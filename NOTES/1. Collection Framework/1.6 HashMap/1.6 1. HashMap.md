# Java HashMap – Overview and Important Key Points

## 1. What is HashMap?

`HashMap` is a class in the Java Collections Framework used to store data in **key-value pairs**.

It is a **hash table-based implementation** of the `Map` interface.

```java
Map<Key, Value> map = new HashMap<>();
```

Example:

```java
Map<String, Integer> ageMap = new HashMap<>();

ageMap.put("Ramesh", 25);
ageMap.put("Suresh", 30);
ageMap.put("Mahesh", 28);
```

Here:

* `"Ramesh"` is the **key**
* `25` is the **value**

---

# 2. HashMap Class Hierarchy

`HashMap` implements the `Map` interface.

Simplified hierarchy:

```text
Map<K, V>
   ↑
HashMap<K, V>
```

Example:

```java
Map<String, Integer> map = new HashMap<>();
```

The commonly preferred declaration is:

```java
Map<String, Integer> map = new HashMap<>();
```

rather than:

```java
HashMap<String, Integer> map = new HashMap<>();
```

This follows the programming principle:

> Program to an interface, not an implementation.

---

# 3. HashMap Stores Key-Value Pairs

Unlike a `List`, which stores individual elements, a `HashMap` stores elements as **key-value pairs**.

Example:

```java
Map<String, Integer> students = new HashMap<>();

students.put("Ramesh", 25);
students.put("Suresh", 30);
students.put("John", 22);
```

Conceptually:

```text
Key       Value
----------------
Ramesh    25
Suresh    30
John      22
```

A value can be retrieved using its corresponding key.

```java
Integer age = students.get("Ramesh");

System.out.println(age);
```

Output:

```text
25
```

---

# 4. HashMap Uses Hashing

Internally, `HashMap` uses a **hashing mechanism** to determine where key-value pairs should be stored.

The key's `hashCode()` plays an important role in determining the location where the entry is stored.

Conceptually:

```text
Key
 |
 v
hashCode()
 |
 v
Hash calculation
 |
 v
Bucket / Location
 |
 v
Key-Value Entry
```

Because of hashing, operations such as:

```java
put()
get()
remove()
```

are generally very fast.

The average time complexity for these operations is approximately:

```text
O(1)
```

assuming a good distribution of hash values.

---

# 5. HashMap Does Not Allow Duplicate Keys

One of the most important rules of `HashMap` is:

> A HashMap cannot contain duplicate keys.

Each key must be unique.

Consider:

```java
Map<String, Integer> map = new HashMap<>();

map.put("Ramesh", 25);
map.put("Ramesh", 28);
```

The second `put()` does **not** create another `"Ramesh"` entry.

Instead, it replaces the old value.

Therefore:

```java
System.out.println(map.get("Ramesh"));
```

Output:

```text
28
```

Conceptually:

```text
Before:

Ramesh -> 25


After:

map.put("Ramesh", 28);


Result:

Ramesh -> 28
```

The old value `25` is replaced by `28`.

---

# 6. Keys Must Be Unique, Values Do Not

Although duplicate keys are not allowed, duplicate **values are allowed**.

Example:

```java
Map<String, Integer> map = new HashMap<>();

map.put("Ramesh", 25);
map.put("Suresh", 25);
map.put("John", 25);
```

This is completely valid.

```text
Ramesh -> 25
Suresh -> 25
John   -> 25
```

Therefore:

```text
Keys   -> Must be unique
Values -> Can be duplicated
```

---

# 7. HashMap Allows One null Key

Java `HashMap` allows a `null` key.

Example:

```java
Map<String, Integer> map = new HashMap<>();

map.put(null, 25);
```

However, because keys must be unique, there can only be **one null key**.

For example:

```java
map.put(null, 25);
map.put(null, 30);
```

The second statement replaces the value associated with the existing `null` key.

Result:

```text
null -> 30
```

Therefore:

```text
HashMap allows only ONE null key.
```

---

# 8. HashMap Allows Multiple null Values

Unlike keys, values do not have to be unique.

Therefore, a `HashMap` can contain multiple `null` values.

Example:

```java
Map<String, Integer> map = new HashMap<>();

map.put("Ramesh", null);
map.put("Suresh", null);
map.put("John", null);
```

This is valid.

```text
Ramesh -> null
Suresh -> null
John   -> null
```

Therefore:

```text
null key    -> Maximum one
null values -> Multiple allowed
```

---

# 9. HashMap is an Unordered Collection

`HashMap` does **not guarantee any specific iteration order**.

For example:

```java
Map<String, Integer> map = new HashMap<>();

map.put("Ramesh", 25);
map.put("Suresh", 30);
map.put("John", 22);
```

Even though the elements were inserted in this order:

```text
Ramesh
Suresh
John
```

you should **not rely on getting them back in the same order** when iterating over the map.

For example:

```java
for (String key : map.keySet()) {
    System.out.println(key);
}
```

The iteration order is not guaranteed.

---

# 10. HashMap vs LinkedHashMap

If insertion order is important, `LinkedHashMap` can be used instead.

### HashMap

```java
Map<String, Integer> map = new HashMap<>();
```

Does **not guarantee insertion order**.

### LinkedHashMap

```java
Map<String, Integer> map = new LinkedHashMap<>();
```

Maintains **insertion order** during normal iteration.

Example insertion:

```text
Ramesh
Suresh
John
```

A `LinkedHashMap` will normally iterate in the same order:

```text
Ramesh
Suresh
John
```

---

# 11. HashMap is Not Thread-Safe

By default, `HashMap` is **not thread-safe**.

This means that when multiple threads access and modify the same `HashMap` concurrently without proper synchronization, problems can occur.

For example:

```text
Thread 1
   |
   |---- modifies HashMap
   |
HashMap
   |
   |---- modifies HashMap
   |
Thread 2
```

Concurrent modifications can result in inconsistent or unexpected behavior.

Therefore, plain `HashMap` should not be used for concurrent modification without appropriate synchronization.

---

# 12. HashMap in a Multi-Threaded Environment

If a map needs to be modified concurrently by multiple threads, one common option is:

```java
ConcurrentHashMap
```

Example:

```java
Map<String, Integer> map = new ConcurrentHashMap<>();
```

Import:

```java
import java.util.concurrent.ConcurrentHashMap;
```

`ConcurrentHashMap` is specifically designed for concurrent access.

Another option is to use synchronization around access to a regular map, depending on the application's requirements.

# 13. Common HashMap Methods

Some important `HashMap` / `Map` methods are:

### put()

Adds or updates a key-value pair.

```java
map.put("Ramesh", 25);
```

### get()

Retrieves the value associated with a key.

```java
map.get("Ramesh");
```

### remove()

Removes a key-value pair.

```java
map.remove("Ramesh");
```

### containsKey()

Checks whether a key exists.

```java
map.containsKey("Ramesh");
```

### containsValue()

Checks whether a value exists.

```java
map.containsValue(25);
```

### size()

Returns the number of key-value mappings.

```java
map.size();
```

### isEmpty()

Checks whether the map is empty.

```java
map.isEmpty();
```

### clear()

Removes all entries.

```java
map.clear();
```

### keySet()

Returns the keys.

```java
map.keySet();
```

### values()

Returns the values.

```java
map.values();
```

### entrySet()

Returns the key-value entries.

```java
map.entrySet();
```

# 14. Simple HashMap Example

```java
import java.util.HashMap;
import java.util.Map;

public class HashMapExample {

    public static void main(String[] args) {

        Map<String, Integer> students = new HashMap<>();

        students.put("Ramesh", 25);
        students.put("Suresh", 30);
        students.put("John", 22);

        System.out.println(students);

        System.out.println(students.get("Ramesh"));

        students.put("Ramesh", 28);

        System.out.println(students.get("Ramesh"));
    }
}
```

The important point is:

```java
students.put("Ramesh", 25);
students.put("Ramesh", 28);
```

The second operation replaces the value `25` with `28`.

# 15. Important HashMap Rules

| Feature                               | HashMap            |
| ------------------------------------- | ------------------ |
| Data structure                        | Key-value pairs    |
| Implements                            | `Map`              |
| Duplicate keys                        | ❌ Not allowed      |
| Duplicate values                      | ✅ Allowed          |
| `null` key                            | ✅ One allowed      |
| `null` values                         | ✅ Multiple allowed |
| Insertion order guaranteed            | ❌ No               |
| Thread-safe                           | ❌ No               |
| Uses hashing                          | ✅ Yes              |
| Typical `get()` / `put()` performance | O(1) average       |

# 17. Quick Revision

Remember these points about `HashMap`:

1. `HashMap` implements the `Map` interface.
2. It stores data as **key-value pairs**.
3. It uses **hashing** internally.
4. Keys must be **unique**.
5. Adding an existing key replaces its old value.
6. Duplicate values are allowed.
7. One `null` key is allowed.
8. Multiple `null` values are allowed.
9. It does not guarantee insertion or iteration order.
10. It is not thread-safe.
11. `LinkedHashMap` can be used when insertion order is required.
12. `ConcurrentHashMap` is designed for concurrent access.

---

```text
HashMap

   +-- Unique keys
   |
   +-- Duplicate values allowed
   |
   +-- One null key
   |
   +-- Multiple null values
   |
```
