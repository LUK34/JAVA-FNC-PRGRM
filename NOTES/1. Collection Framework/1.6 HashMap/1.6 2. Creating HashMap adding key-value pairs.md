# Java HashMap – Creating a HashMap and Adding Key-Value Pairs

## 1. Objective

In this example, we will learn:

* How to create a `HashMap`
* How to add key-value pairs using `put()`
* How to use `putIfAbsent()`
* What happens when we add a duplicate key
* How `HashMap` handles `null` keys
* How `HashMap` handles `null` values
* How to print a `HashMap`

---

# 2. Creating a HashMap

A `HashMap` can be created using the `HashMap` class.

Example:

```java
Map<String, Integer> numberMapping = new HashMap<>();
```

Required imports:

```java
import java.util.HashMap;
import java.util.Map;
```

Here:

```text
Map<String, Integer>
     |        |
     |        +---- Value Type
     |
     +------------- Key Type
```

Therefore:

```java
Map<String, Integer> numberMapping = new HashMap<>();
```

means:

* Key type = `String`
* Value type = `Integer`

Example data:

```text
"One"   -> 1
"Two"   -> 2
"Three" -> 3
```

---

# 3. Why Use Map as the Reference Type?

Instead of:

```java
HashMap<String, Integer> numberMapping = new HashMap<>();
```

we commonly write:

```java
Map<String, Integer> numberMapping = new HashMap<>();
```

This means:

```text
Reference Type       Object Type
     |                    |
     v                    v
    Map      =        HashMap
```

This follows the principle:

> Program to an interface, not an implementation.

It also makes it easier to change the implementation later.

For example:

```java
Map<String, Integer> numberMapping = new LinkedHashMap<>();
```

or:

```java
Map<String, Integer> numberMapping = new TreeMap<>();
```

without changing most of the remaining code.

---

# 4. Default Initial Capacity of HashMap

When we create an empty `HashMap`:

```java
Map<String, Integer> numberMapping = new HashMap<>();
```

the default initial capacity associated with `HashMap` is:

```text
16
```

This is an important interview point.

> **Default initial capacity of HashMap = 16**

However, this should not be confused with the number of elements currently stored in the map.

For example:

```java
Map<String, Integer> numberMapping = new HashMap<>();
```

At this point:

```text
Number of entries = 0
```

The map is still empty.

---

# 5. Adding Key-Value Pairs Using put()

The `put()` method is used to add a key-value mapping to a `Map`.

Syntax:

```java
map.put(key, value);
```

Example:

```java
numberMapping.put("One", 1);
numberMapping.put("Two", 2);
numberMapping.put("Three", 3);
```

Conceptually:

```text
Key       Value
----------------
One   ->    1
Two   ->    2
Three ->    3
```

---

# 6. put() Method

The general method signature is:

```java
V put(K key, V value)
```

Where:

```text
K = Key type
V = Value type
```

For our map:

```java
Map<String, Integer> numberMapping
```

the types are:

```text
K = String
V = Integer
```

Therefore:

```java
numberMapping.put("One", 1);
```

stores:

```text
"One" -> 1
```

---

# 7. Return Value of put()

An important detail about `put()` is that it returns the **previous value associated with the key**.

Example:

```java
Integer previousValue = numberMapping.put("One", 1);
```

If `"One"` did not previously exist, the returned value is normally:

```text
null
```

If the key already exists:

```java
numberMapping.put("One", 1);

Integer oldValue = numberMapping.put("One", 5);
```

then:

```text
oldValue = 1
```

because `1` was the previous value associated with `"One"`.

---

# 8. Adding an Entry Using putIfAbsent()

Java also provides:

```java
putIfAbsent()
```

Example:

```java
numberMapping.putIfAbsent("Four", 4);
```

`putIfAbsent()` adds the mapping when the key is not already associated with a non-null value.

Conceptually:

```text
Before:

One   -> 1
Two   -> 2
Three -> 3


Execute:

numberMapping.putIfAbsent("Four", 4);


After:

One   -> 1
Two   -> 2
Three -> 3
Four  -> 4
```

---

# 9. put() vs putIfAbsent()

This is an important difference.

### put()

```java
numberMapping.put("One", 5);
```

If `"One"` already exists, its value is replaced.

### putIfAbsent()

```java
numberMapping.putIfAbsent("One", 5);
```

If `"One"` already has a non-null value, it is **not replaced**.

Example:

```java
Map<String, Integer> map = new HashMap<>();

map.put("One", 1);
map.putIfAbsent("One", 5);

System.out.println(map);
```

The mapping remains:

```text
One -> 1
```

not:

```text
One -> 5
```

---

# 10. putIfAbsent() and null Values

There is an important detail about `putIfAbsent()`.

Suppose:

```java
map.put("One", null);
```

Now execute:

```java
map.putIfAbsent("One", 1);
```

Because `"One"` is currently mapped to `null`, `putIfAbsent()` can associate it with `1`.

Result:

```text
One -> 1
```

Therefore, a useful way to remember `putIfAbsent()` is:

> Add the value if the key is absent or currently mapped to `null`.

---

# 11. Printing a HashMap

We can print the entire map using:

```java
System.out.println(numberMapping);
```

Example output could look like:

```text
{One=1, Two=2, Three=3, Four=4}
```

Each entry is displayed conceptually as:

```text
key=value
```

---

# 12. HashMap Does Not Guarantee Insertion Order

Suppose we insert:

```java
numberMapping.put("One", 1);
numberMapping.put("Two", 2);
numberMapping.put("Three", 3);
numberMapping.put("Four", 4);
```

Insertion order:

```text
One
Two
Three
Four
```

When the map is printed or iterated, you should **not rely on the entries appearing in that same order**.

`HashMap` does not guarantee insertion order.

Therefore:

```text
Insertion Order
      |
      v
One -> Two -> Three -> Four

does NOT guarantee

Iteration Order
      |
      v
One -> Two -> Three -> Four
```

If insertion order must be maintained, consider:

```java
LinkedHashMap
```

---

# 13. Adding a Duplicate Key Using put()

`HashMap` does not allow duplicate keys.

Consider:

```java
numberMapping.put("One", 1);
```

Later:

```java
numberMapping.put("One", 5);
```

The key `"One"` already exists.

Therefore, the existing value is replaced.

Before:

```text
One -> 1
```

After:

```java
numberMapping.put("One", 5);
```

Result:

```text
One -> 5
```

The map does **not** become:

```text
One -> 1
One -> 5
```

because duplicate keys are not allowed.

---

# 14. Duplicate Key Rule

Remember:

```text
HashMap
   |
   +---- Key must be unique
   |
   +---- Value does NOT have to be unique
```

For example:

```java
map.put("One", 1);
map.put("Two", 1);
map.put("Three", 1);
```

is valid because the keys are different.

```text
One   -> 1
Two   -> 1
Three -> 1
```

---

# 15. HashMap Allows a null Key

A `HashMap` allows a `null` key.

Example:

```java
numberMapping.put(null, null);
```

This is valid.

Conceptually:

```text
null -> null
```

A `HashMap` can contain at most **one null key**, because keys must be unique.

---

# 16. What Happens With Multiple null Keys?

Consider:

```java
numberMapping.put(null, 10);
numberMapping.put(null, 20);
```

There will still be only one `null` key.

The second `put()` updates the value associated with that key.

Result:

```text
null -> 20
```

It is more accurate to say that the second call **replaces the existing value** rather than saying the duplicate key is ignored.

This follows the same rule as any other duplicate key.

---

# 17. HashMap Allows Multiple null Values

Although only one `null` key is allowed, multiple keys can have `null` values.

Example:

```java
numberMapping.put("Five", null);
numberMapping.put("Six", null);
numberMapping.put("Seven", null);
```

This is valid.

Result:

```text
Five  -> null
Six   -> null
Seven -> null
```

Why?

Because:

```text
Keys   -> Must be unique
Values -> Can be duplicated
```

Since `null` is being used as a value, it can appear multiple times.

---

# 18. null Key vs null Values

| Feature                | HashMap     |
| ---------------------- | ----------- |
| `null` key             | One allowed |
| Multiple `null` keys   | ❌ No        |
| `null` values          | ✅ Allowed   |
| Multiple `null` values | ✅ Allowed   |

Example:

```java
Map<String, Integer> map = new HashMap<>();

map.put(null, null);
map.put("One", null);
map.put("Two", null);
```

Valid map:

```text
null -> null
One  -> null
Two  -> null
```

---

# 19. Complete Example

```java
import java.util.HashMap;
import java.util.Map;

public class CreateHashMapExample {

    public static void main(String[] args) {

        // Create HashMap
        Map<String, Integer> numberMapping = new HashMap<>();

        // Add key-value pairs using put()
        numberMapping.put("One", 1);
        numberMapping.put("Two", 2);
        numberMapping.put("Three", 3);

        // Add a value only when appropriate
        numberMapping.putIfAbsent("Four", 4);

        // Print HashMap
        System.out.println(numberMapping);

        // Duplicate key - existing value will be replaced
        numberMapping.put("One", 5);

        System.out.println(numberMapping);

        // HashMap allows one null key
        numberMapping.put(null, null);

        // Multiple null values are allowed
        numberMapping.put("Five", null);
        numberMapping.put("Six", null);

        System.out.println(numberMapping);
    }
}
```

---

# 20. put() vs putIfAbsent() – Quick Comparison

| Method                    | Key Doesn't Exist | Key Exists With Value         | Key Maps to `null`   |
| ------------------------- | ----------------- | ----------------------------- | -------------------- |
| `put(key, value)`         | Adds mapping      | Replaces value                | Replaces `null`      |
| `putIfAbsent(key, value)` | Adds mapping      | Keeps existing non-null value | Associates new value |

Example:

```java
map.put("One", 1);
map.put("One", 5);
```

Result:

```text
One -> 5
```

But:

```java
map.put("One", 1);
map.putIfAbsent("One", 5);
```

Result:

```text
One -> 1
```

# 21. Important Interview Points

### What is the default initial capacity of HashMap?

```text
16
```

### Does HashMap allow duplicate keys?

```text
No
```

### What happens when put() is called with an existing key?

The existing value is replaced with the new value.

### Does HashMap allow duplicate values?

```text
Yes
```

### Does HashMap allow a null key?

```text
Yes, one null key.
```

### Does HashMap allow null values?

```text
Yes, multiple null values.
```

### Does HashMap maintain insertion order?

```text
No
```

### Which method prevents overwriting an existing non-null mapping?

```java
putIfAbsent()
```

# Key Takeaway

The two most important methods from this lecture are:

```java
map.put(key, value);
map.putIfAbsent(key, value);
```

Remember the difference:

> **`put()` can replace the value of an existing key, while `putIfAbsent()` preserves an existing non-null mapping.**

And the fundamental `HashMap` rule remains:

> **Keys are unique, but values can be duplicated.**
