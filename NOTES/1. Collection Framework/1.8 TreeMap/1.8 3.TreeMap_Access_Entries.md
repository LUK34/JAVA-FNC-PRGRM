# Java `TreeMap` --- Accessing Entries with `NavigableMap`

## Overview

This lesson explains how to access and navigate entries in a Java
`TreeMap`.

You will learn how to:

1.  Create a `TreeMap` using `NavigableMap` as the reference type.
2.  Find the number of entries with `size()`.
3.  Check whether a key exists with `containsKey()`.
4.  Retrieve the first entry with `firstEntry()`.
5.  Retrieve the last entry with `lastEntry()`.
6.  Find the entry immediately lower than a key with `lowerEntry()`.
7.  Find the entry immediately higher than a key with `higherEntry()`.
8.  Understand why `lowerEntry()` and `higherEntry()` can return `null`.

All examples are compatible with **Java 8**.

------------------------------------------------------------------------

# 1. Why Use `NavigableMap`?

`TreeMap` implements the `NavigableMap` interface.

The important hierarchy is:

``` text
Map
 ↑
SortedMap
 ↑
NavigableMap
 ↑
TreeMap
```

`SortedMap` provides sorted-map behavior.

`NavigableMap` adds methods for navigating around sorted keys.

Examples:

``` java
firstEntry()
lastEntry()
lowerEntry()
higherEntry()
floorEntry()
ceilingEntry()
```

Therefore, for this lesson we can write:

``` java
NavigableMap<String, Double> productPrices =
        new TreeMap<>();
```

------------------------------------------------------------------------

# 2. Create the TreeMap

Required imports:

``` java
import java.util.Map;
import java.util.NavigableMap;
import java.util.TreeMap;
```

Create the map:

``` java
NavigableMap<String, Double> productPrices =
        new TreeMap<>();
```

Here:

``` text
String
   ↓
KEY = Product Name

Double
   ↓
VALUE = Product Price
```

------------------------------------------------------------------------

# 3. Add Product-Price Entries

For example:

``` java
productPrices.put("Laptop", 1200.00);
productPrices.put("Smartphone", 800.00);
productPrices.put("Tablet", 500.00);
productPrices.put("Monitor", 300.00);
```

Notice the insertion order:

``` text
Laptop
Smartphone
Tablet
Monitor
```

But `TreeMap` does not normally iterate according to insertion order.

It sorts the keys according to their ordering rule.

With natural `String` ordering:

``` text
Laptop
Monitor
Smartphone
Tablet
```

Therefore:

``` java
System.out.println(productPrices);
```

produces a map ordered by product-name key.

------------------------------------------------------------------------

# 4. Important: "First" and "Last" Mean Sorted Order

This concept is critical.

Suppose:

``` java
productPrices.put("Laptop", 1200.00);
productPrices.put("Smartphone", 800.00);
productPrices.put("Tablet", 500.00);
productPrices.put("Monitor", 300.00);
```

The last inserted entry was:

``` text
Monitor
```

But after TreeMap sorting:

``` text
Laptop
  ↓
Monitor
  ↓
Smartphone
  ↓
Tablet
```

So:

``` java
firstEntry()
```

returns the entry with key:

``` text
Laptop
```

and:

``` java
lastEntry()
```

returns the entry with key:

``` text
Tablet
```

It does **not** mean first/last inserted.

``` java

```

returns:

``` text
4
```

### Meaning

``` text
size()
   ↓
Number of key-value mappings
```

# 6. Check Whether a Key Exists with `containsKey()`

Use:

``` java
productPrices.containsKey(key);
```

It returns a boolean:

``` text
true
or
false
```

Example:

``` java
String key = "Tablet";

if (productPrices.containsKey(key)) {

    System.out.println(
            key + " exists in the TreeMap"
    );

} else {

    System.out.println(
            key + " does not exist in the TreeMap"
    );
}
```

Since `"Tablet"` exists:

``` text
Tablet exists in the TreeMap
```

------------------------------------------------------------------------

# 7. `containsKey()` Flow

``` text
Given key
   |
   v
"Tablet"
   |
   v
containsKey("Tablet")
   |
   +------ true ------> Key exists
   |
   +------ false -----> Key does not exist
```

This is useful before attempting logic that depends on a particular key.

# 8. Retrieve the First Entry with `firstEntry()`

Use:

``` java
productPrices.firstEntry();
```

The return type is:

``` java
Map.Entry<String, Double>
```

Example:

``` java
Map.Entry<String, Double> firstEntry =
        productPrices.firstEntry();

System.out.println(
        "First product: " + firstEntry
);
```

With sorted keys:

``` text
Laptop
Monitor
Smartphone
Tablet
```

the first entry is:

``` text
Laptop=1200.0
```

------------------------------------------------------------------------

# 9. Understanding `Map.Entry`

A map entry represents one key-value pair.

For example:

``` text
Laptop → 1200.00
```

is represented by:

``` java
Map.Entry<String, Double>
```

You can access its components:

``` java
firstEntry.getKey();
firstEntry.getValue();
```

Example:

``` java
System.out.println(firstEntry.getKey());
System.out.println(firstEntry.getValue());
```

Conceptually:

``` text
Map.Entry
│
├── getKey()   → Laptop
│
└── getValue() → 1200.00
```

Use:

``` java
productPrices.lastEntry();
```

Example:

``` java
Map.Entry<String, Double> lastEntry =
        productPrices.lastEntry();

```

Given:

``` text
Laptop
Monitor
Smartphone
Tablet
```

``` text
Tablet=500.0
```

------------------------------------------------------------------------

# 11. `firstEntry()` vs `lastEntry()`

``` text
Sorted TreeMap:

Laptop
   ↓
Monitor
   ↓
Smartphone
   ↓
Tablet
```

Therefore:

``` text
firstEntry()
     ↓
Laptop


lastEntry()
     ↓
Tablet
```

------------------------------------------------------------------------

# 12. Find the Entry Just Lower Than a Key

`NavigableMap` provides:

``` java
lowerEntry(key)
```

It returns the entry associated with the **greatest key strictly less
than** the given key according to the map's ordering.

Example:

``` java
Map.Entry<String, Double> lowerEntry =
        productPrices.lowerEntry("Tablet");

System.out.println(
        "Lower entry: " + lowerEntry
);
```

Sorted keys:

``` text
Laptop
Monitor
Smartphone
Tablet
```

The key immediately below `"Tablet"` is:

``` text
Smartphone
```

Therefore:

``` text
lowerEntry("Tablet")
        ↓
Smartphone=800.0
```

------------------------------------------------------------------------

# 13. What Does "Lower" Really Mean?

It does **not** mean a lower price.

It means a lower **key according to the TreeMap's ordering**.

This is important because the values are prices, but TreeMap navigation
is based on keys.

``` text
KEY
 ↓
"Tablet"

lowerEntry("Tablet")
        ↓
Search sorted KEYS
        ↓
"Smartphone"
```

The price values are irrelevant to determining which entry is lower.

------------------------------------------------------------------------

# 14. Find the Entry Just Higher Than a Key

Use:

``` java
higherEntry(key)
```

It returns the entry associated with the **least key strictly greater
than** the given key.

Example:

``` java
Map.Entry<String, Double> higherEntry =
        productPrices.higherEntry("Smartphone");

System.out.println(
        "Higher entry: " + higherEntry
);
```

Sorted keys:

``` text
Laptop
Monitor
Smartphone
Tablet
```

The next greater key after `"Smartphone"` is:

``` text
Tablet
```

Therefore:

``` text
higherEntry("Smartphone")
        ↓
Tablet=500.0
```

------------------------------------------------------------------------

# 15. Why Can `higherEntry()` Return `null`?

Consider:

``` java
productPrices.higherEntry("Tablet");
```

`"Tablet"` is already the greatest key in this map.

``` text
Laptop
Monitor
Smartphone
Tablet
          ↑
        Last key
```

There is no greater key.

Therefore:

``` java
higherEntry("Tablet")
```

returns:

``` text
null
```

This is normal behavior.

------------------------------------------------------------------------

# 16. `lowerEntry()` Can Also Return `null`

If you call:

``` java
productPrices.lowerEntry("Laptop");
```

`"Laptop"` is the smallest key.

There is nothing strictly lower.

Therefore:

``` text
lowerEntry("Laptop")
```

returns:

``` text
null
```

So always remember that navigation methods can have no matching entry.

------------------------------------------------------------------------

# 17. Strictly Lower and Strictly Higher

The words **strictly** are important.

Suppose keys are:

``` text
10
20
30
40
```

Then:

``` text
lowerEntry(30)
      ↓
20
```

not:

``` text
30
```

Similarly:

``` text
higherEntry(30)
       ↓
40
```

not:

``` text
30
```

Easy rule:

``` text
lower  → <
higher → >
```

------------------------------------------------------------------------

# 18. Related Methods: `floorEntry()` and `ceilingEntry()`

Although the lecture focuses on `lowerEntry()` and `higherEntry()`,
`NavigableMap` also provides closely related methods.

``` java
floorEntry(key)
ceilingEntry(key)
```

The complete rule is:

``` text
lowerEntry()   → <
floorEntry()   → <=

ceilingEntry() → >=
higherEntry()  → >
```

Example keys:

``` text
10   20   30   40
```

For key `30`:

``` text
lowerEntry(30)   → 20
floorEntry(30)   → 30
ceilingEntry(30) → 30
higherEntry(30)  → 40
```

This is an excellent interview memory trick.

------------------------------------------------------------------------

# 19. Complete Runnable Example

``` java
import java.util.Map;
import java.util.NavigableMap;
import java.util.TreeMap;

public class AccessTreeMapExample {

    public static void main(String[] args) {

        NavigableMap<String, Double> productPrices =
                new TreeMap<>();

        productPrices.put("Laptop", 1200.00);
        productPrices.put("Smartphone", 800.00);
        productPrices.put("Tablet", 500.00);
        productPrices.put("Monitor", 300.00);

        // Print TreeMap
        System.out.println(
                "Product Prices: " +
                productPrices
        );

        // --------------------------------
        // 1. size()
        // --------------------------------

        System.out.println(
                "Size of TreeMap: " +
                productPrices.size()
        );

        // --------------------------------
        // 2. containsKey()
        // --------------------------------

        String key = "Tablet";

        if (productPrices.containsKey(key)) {

            System.out.println(
                    key +
                    " exists in the TreeMap"
            );

        } else {

            System.out.println(
                    key +
                    " does not exist in the TreeMap"
            );
        }

        // --------------------------------
        // 3. firstEntry()
        // --------------------------------

        Map.Entry<String, Double> firstEntry =
                productPrices.firstEntry();

        System.out.println(
                "First product: " +
                firstEntry
        );

        // --------------------------------
        // 4. lastEntry()
        // --------------------------------

        Map.Entry<String, Double> lastEntry =
                productPrices.lastEntry();

        System.out.println(
                "Last product: " +
                lastEntry
        );

        // --------------------------------
        // 5. lowerEntry()
        // --------------------------------

        Map.Entry<String, Double> lowerEntry =
                productPrices.lowerEntry("Tablet");

        System.out.println(
                "Entry lower than Tablet: " +
                lowerEntry
        );

        // --------------------------------
        // 6. higherEntry()
        // --------------------------------

        Map.Entry<String, Double> higherEntry =
                productPrices.higherEntry(
                        "Smartphone"
                );

        System.out.println(
                "Entry higher than Smartphone: " +
                higherEntry
        );

        // No entry is higher than Tablet
        System.out.println(
                "Entry higher than Tablet: " +
                productPrices.higherEntry("Tablet")
        );
    }
}
```

# 23. Important Empty-Map Behavior

If the `TreeMap` is empty:

``` java
NavigableMap<String, Double> map =
        new TreeMap<>();
```

then:

``` java
map.firstEntry();
map.lastEntry();
```

return:

``` text
null
```

This is useful because `firstEntry()` and `lastEntry()` can be checked
safely:

``` java
Map.Entry<String, Double> entry =
        map.firstEntry();

if (entry != null) {
    System.out.println(entry);
}
```

# 24. `firstEntry()` vs `firstKey()`

Do not confuse these.

### `firstEntry()`

Returns:

``` java
Map.Entry<K,V>
```

So you get:

``` text
KEY + VALUE
```

### `firstKey()`

Returns:

``` java
K
```

So you get only:

``` text
KEY
```

Example:

``` java
productPrices.firstEntry();
```

might return:

``` text
Laptop=1200.0
```

while:

``` java
productPrices.firstKey();
```

returns:

``` text
Laptop
```

The same distinction exists between:

``` java
lastEntry()
```

and:

``` java
lastKey()
```

------------------------------------------------------------------------

# 25. Entry Methods vs Key Methods

`NavigableMap` provides both styles.

``` text
Need KEY + VALUE?
        |
        v
Use Entry method
```

Examples:

``` java
lowerEntry()
higherEntry()
floorEntry()
ceilingEntry()
firstEntry()
lastEntry()
```

If you only need the key:

``` text
Need only KEY?
     |
     v
Use Key method
```

Examples:

``` java
lowerKey()
higherKey()
floorKey()
ceilingKey()
firstKey()
lastKey()
```

# 26. Common Beginner Mistakes

## Mistake 1 --- Thinking `firstEntry()` means first inserted

It does not.

It means:

``` text
Entry with the smallest key
according to the map's ordering.
```

------------------------------------------------------------------------

## Mistake 2 --- Thinking `lastEntry()` means last inserted

It means:

``` text
Entry with the greatest key
according to the map's ordering.
```

------------------------------------------------------------------------

## Mistake 3 --- Thinking `lowerEntry()` compares values

Incorrect:

``` text
Compare product prices
```

Correct:

``` text
Compare product-name KEYS
```

TreeMap navigation is based on key ordering.

------------------------------------------------------------------------

## Mistake 4 --- Forgetting that `higherEntry()` can return null

If no greater key exists:

``` java
map.higherEntry(key)
```

returns:

``` text
null
```

The same idea applies to `lowerEntry()` when there is no lower key.

------------------------------------------------------------------------

## Mistake 5 --- Confusing `lower` with `floor`

Remember:

``` text
lower → strictly <
floor → <=
```

Likewise:

``` text
higher  → strictly >
ceiling → >=
```

# 28. Interview / Exam Points

1.  `TreeMap` implements `NavigableMap`.
2.  `NavigableMap` extends `SortedMap`.
3.  `size()` returns the number of key-value mappings.
4.  `containsKey()` returns `true` or `false`.
5.  `firstEntry()` returns the entry with the smallest key according to
    the map's ordering.
6.  `lastEntry()` returns the entry with the greatest key.
7.  `lowerEntry(key)` searches for the greatest key strictly less than
    the supplied key.
8.  `higherEntry(key)` searches for the least key strictly greater than
    the supplied key.
9.  `lowerEntry()` can return `null`.
10. `higherEntry()` can return `null`.
11. TreeMap navigation operates on **keys**, not values.
12. `firstEntry()` and `lastEntry()` return `null` for an empty
    navigable map.
13. `lower` means `<`.
14. `floor` means `<=`.
15. `ceiling` means `>=`.
16. `higher` means `>`.
17. `firstEntry()` returns key + value, while `firstKey()` returns only
    the key.
18. A custom comparator changes the ordering used by these navigation
    operations.

# Final Summary

The central idea of this lecture is that `TreeMap` is not only
sorted---it is also **navigable**.

Given:

``` text
Laptop
Monitor
Smartphone
Tablet
```

you can ask:

``` text
What is first?
    → Laptop

What is last?
    → Tablet

What is immediately lower than Tablet?
    → Smartphone

What is immediately higher than Smartphone?
    → Tablet
```

The core methods are:

``` java
size()
containsKey()

firstEntry()
lastEntry()

lowerEntry()
higherEntry()
```

And the most important navigation rule to remember is:

``` text
lower   → <
floor   → <=

ceiling → >=
higher  → >
```

All of these ordering and navigation operations are based on the
**TreeMap's key ordering**, whether that ordering comes from natural
ordering or a custom `Comparator`.
