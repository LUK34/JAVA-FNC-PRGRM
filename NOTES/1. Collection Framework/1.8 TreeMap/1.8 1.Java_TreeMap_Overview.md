# Java `TreeMap` --- Overview and Important Key Points

## Overview

`TreeMap` is a Java Collections Framework implementation used to store
**key-value pairs in sorted key order**.

Unlike `HashMap` and the default insertion-order form of
`LinkedHashMap`, a `TreeMap` automatically orders its entries according
to:

-   the **natural ordering** of its keys, or
-   a **custom `Comparator`** supplied when the `TreeMap` is created.

This lesson covers the most important concepts you should understand
before working with `TreeMap`.

------------------------------------------------------------------------

# 1. Where Does `TreeMap` Belong?

`TreeMap` is part of the Java Collections Framework.

Import it using:

``` java
import java.util.TreeMap;
```

It implements the `NavigableMap` interface.

The important hierarchy is:

``` text
Map
 ↑
SortedMap
 ↑
NavigableMap
 ↑
TreeMap
```

More precisely:

``` text
Map<K,V>
    ↑
SortedMap<K,V>
    ↑
NavigableMap<K,V>
    ↑
TreeMap<K,V>
```

So a `TreeMap` gets functionality from both:

``` text
SortedMap
    +
NavigableMap
```

------------------------------------------------------------------------

# 2. What Does `SortedMap` Provide?

`SortedMap` represents a map whose keys are maintained in sorted order.

Conceptually:

``` text
Unsorted input:

5 → Five
1 → One
3 → Three


TreeMap:

1 → One
3 → Three
5 → Five
```

The sorting applies to the **keys**.

This is an important point:

> `TreeMap` sorts entries according to their keys, not their values.

------------------------------------------------------------------------

# 3. What Does `NavigableMap` Provide?

`NavigableMap` extends `SortedMap` and adds methods that help navigate
around keys.

For example, it provides operations for finding:

-   a key lower than another key;
-   a key higher than another key;
-   a key less than or equal to another key;
-   a key greater than or equal to another key;
-   the first entry;
-   the last entry.

Some important methods include:

``` java
lowerKey()
floorKey()
ceilingKey()
higherKey()

firstKey()
lastKey()

firstEntry()
lastEntry()
```

Visual idea:

``` text
10      20      30      40      50
         ↑
       Given key

lowerKey(20)
    → 10

higherKey(20)
    → 30
```

This navigational functionality is one of the major differences between
`TreeMap` and simpler map implementations.

------------------------------------------------------------------------

# 4. TreeMap Automatically Sorts Keys

Consider:

``` java
TreeMap<Integer, String> numbers =
        new TreeMap<>();

numbers.put(30, "Thirty");
numbers.put(10, "Ten");
numbers.put(20, "Twenty");

System.out.println(numbers);
```

Even though the insertion order was:

``` text
30
10
20
```

the output is:

``` text
{10=Ten, 20=Twenty, 30=Thirty}
```

Why?

Because `Integer` has a natural ordering:

``` text
10 < 20 < 30
```

------------------------------------------------------------------------

# 5. Natural Ordering

By default, a `TreeMap` uses the **natural ordering of its keys**.

For numbers:

``` text
1
2
3
4
5
```

For strings, ordering follows the natural ordering defined by
`String.compareTo()`.

Example:

``` java
TreeMap<String, Integer> map =
        new TreeMap<>();

map.put("Orange", 3);
map.put("Apple", 1);
map.put("Banana", 2);

System.out.println(map);
```

Output:

``` text
{Apple=1, Banana=2, Orange=3}
```

Conceptually:

``` text
Inserted:
Orange
Apple
Banana

        ↓ TreeMap sorting

Iteration:
Apple
Banana
Orange
```

------------------------------------------------------------------------

# 6. Custom Ordering with `Comparator`

You are not limited to natural ordering.

A custom `Comparator` can be supplied when creating the `TreeMap`.

For example, reverse order:

``` java
import java.util.Collections;
import java.util.Map;
import java.util.TreeMap;

Map<Integer, String> map =
        new TreeMap<>(Collections.reverseOrder());

map.put(10, "Ten");
map.put(30, "Thirty");
map.put(20, "Twenty");

System.out.println(map);
```

Output:

``` text
{30=Thirty, 20=Twenty, 10=Ten}
```

Now the keys follow:

``` text
30
 ↓
20
 ↓
10
```

instead of ascending order.

------------------------------------------------------------------------

# 7. Natural Ordering vs Custom Comparator

``` text
TreeMap
   |
   +--------------------------+
   |                          |
Natural Ordering        Custom Comparator
   |                          |
Default                    Supplied by
behavior                   developer
   |                          |
Ascending /               Any valid
natural key order         custom ordering
```

Example:

``` java
new TreeMap<>();
```

uses natural ordering.

Example:

``` java
new TreeMap<>(comparator);
```

uses the supplied comparator.

------------------------------------------------------------------------

# 8. TreeMap Does Not Allow Duplicate Keys

Like all `Map` implementations, `TreeMap` requires keys to be unique.

Example:

``` java
TreeMap<Integer, String> map =
        new TreeMap<>();

map.put(1, "Java");
map.put(1, "Spring Boot");
```

This does **not** create:

``` text
1 → Java
1 → Spring Boot
```

Instead, the second `put()` replaces the value associated with key `1`.

The map becomes:

``` text
1 → Spring Boot
```

Think:

``` text
put(1, "Java")
       ↓
1 → Java

put(1, "Spring Boot")
       ↓
Existing key found
       ↓
Replace value
       ↓
1 → Spring Boot
```

------------------------------------------------------------------------

# 9. Duplicate Values Are Allowed

Keys must be unique, but values do not have to be unique.

This is valid:

``` java
TreeMap<Integer, String> map =
        new TreeMap<>();

map.put(1, "Java");
map.put(2, "Java");
map.put(3, "Java");
```

Result:

``` text
1 → Java
2 → Java
3 → Java
```

So remember:

``` text
Duplicate KEY
    → Not stored as a separate mapping

Duplicate VALUE
    → Allowed
```

------------------------------------------------------------------------

# 10. Null Keys

For a normally constructed `TreeMap` using natural ordering, you should
treat `null` keys as **not permitted**.

Example:

``` java
TreeMap<String, Integer> map =
        new TreeMap<>();

map.put(null, 10);
```

This results in a `NullPointerException`.

Why?

A `TreeMap` must compare keys to determine their sorted position.

Conceptually:

``` text
"Apple".compareTo("Banana")
          ↓
Can determine order


null
 ↓
Cannot participate in normal natural ordering
```

Therefore, avoid null keys in `TreeMap`.

> Advanced note: `TreeMap` behavior is ultimately governed by its
> comparator when one is supplied. A specially written comparator can
> theoretically define how `null` should compare. For normal
> natural-order `TreeMap` usage, however, null keys are not supported.

------------------------------------------------------------------------

# 11. Null Values Are Allowed

A `TreeMap` can contain `null` values.

Example:

``` java
TreeMap<Integer, String> map =
        new TreeMap<>();

map.put(1, "Java");
map.put(2, null);
map.put(3, "Spring");
```

This is valid:

``` text
1 → Java
2 → null
3 → Spring
```

Why?

The map sorts using the **keys**:

``` text
1
2
3
```

The values are not used to determine key ordering.

------------------------------------------------------------------------

# 12. Null Key vs Null Value

  Feature                                 TreeMap
  --------------------------------------- ---------
  Null key with normal natural ordering   No
  Null values                             Yes
  Duplicate keys                          No
  Duplicate values                        Yes

Easy memory:

``` text
TreeMap sorts KEYS.

Therefore:

KEY must be sortable/comparable.
VALUE does not determine ordering.
```

------------------------------------------------------------------------

# 13. TreeMap Is Not Synchronized

`TreeMap` is not synchronized by default.

That means it should not automatically be assumed to be thread-safe when
multiple threads concurrently modify the same instance.

Conceptually:

``` text
Thread A ──┐
           ├──→ Same TreeMap
Thread B ──┘
```

If concurrent access includes structural modification and there is no
appropriate synchronization, problems can occur.

------------------------------------------------------------------------

# 14. Synchronizing a TreeMap

Java's `Collections` utility class provides:

``` java
Collections.synchronizedSortedMap(...)
```

For example:

``` java
import java.util.Collections;
import java.util.SortedMap;
import java.util.TreeMap;

SortedMap<Integer, String> map =
        Collections.synchronizedSortedMap(
                new TreeMap<Integer, String>()
        );
```

This creates a synchronized wrapper around the sorted map.

If you only require the general `Map` API,
`Collections.synchronizedMap(...)` is also available, but
`synchronizedSortedMap(...)` preserves the `SortedMap` interface in the
reference.

Thread safety is a broader topic, and compound operations or iteration
may still require correct synchronization according to the wrapper's
contract.

------------------------------------------------------------------------

# 15. Basic TreeMap Example

``` java
import java.util.Map;
import java.util.TreeMap;

public class TreeMapExample {

    public static void main(String[] args) {

        Map<Integer, String> students =
                new TreeMap<>();

        students.put(30, "John");
        students.put(10, "David");
        students.put(20, "Sarah");
        students.put(40, "Michael");

        System.out.println(students);
    }
}
```

Output:

``` text
{10=David, 20=Sarah, 30=John, 40=Michael}
```

Notice:

``` text
Insertion order:

30 → 10 → 20 → 40


TreeMap iteration order:

10 → 20 → 30 → 40
```

# 16. TreeMap vs HashMap vs LinkedHashMap

This distinction is very important.

  -----------------------------------------------------------------------
  Feature           HashMap           LinkedHashMap     TreeMap
  ----------------- ----------------- ----------------- -----------------
  Key ordering      No guaranteed     Predictable       Sorted key order
                    iteration order   order, commonly   
                                      insertion order   

  Duplicate keys    No                No                No

  Duplicate values  Yes               Yes               Yes

  Null key          Typically one     Typically one     Not with normal
                                                        natural ordering

  Null values       Yes               Yes               Yes

  Navigation        No                No                Yes
  methods                                               

  Thread-safe by    No                No                No
  default                                               
  -----------------------------------------------------------------------

A simple decision rule:

``` text
Need key-value storage?
        |
        v
Does order matter?
   |             |
  NO            YES
   |             |
HashMap     What kind of order?
                |
          +-----+------+
          |            |
      Insertion      Sorted
        order          keys
          |            |
   LinkedHashMap     TreeMap
```

# 17. Internal Data Structure

`TreeMap` is based on a **Red-Black tree**, which is a self-balancing
binary search tree.

High-level idea:

``` text
             20
           /    \
         10      40
                /  \
              30    50
```

The actual Red-Black tree also maintains balancing information.

You do not need to manually balance it.

`TreeMap` manages this internally.

This structure is what enables sorted traversal and navigation around
keys.

------------------------------------------------------------------------

# 18. Performance

Common `TreeMap` operations generally take:

``` text
O(log n)
```

including:

``` java
put()
get()
remove()
```

By comparison, `HashMap` commonly provides average-case:

``` text
O(1)
```

for basic lookup/insertion/removal.

So why use `TreeMap`?

Because it provides capabilities such as:

``` text
Sorted keys
+
Navigation
+
Range-oriented operations
```

that a normal `HashMap` does not provide.

------------------------------------------------------------------------

# 19. Important Navigational Methods

Because `TreeMap` implements `NavigableMap`, methods include:

``` java
lowerKey(key)
floorKey(key)
ceilingKey(key)
higherKey(key)
```

Suppose keys are:

``` text
10   20   30   40   50
```

For key `30`:

``` text
lowerKey(30)
    → 20

floorKey(30)
    → 30

ceilingKey(30)
    → 30

higherKey(30)
    → 40
```

Think:

``` text
lower   → strictly <
floor   → <=

ceiling → >=
higher  → strictly >
```

This is an excellent interview memory trick.

------------------------------------------------------------------------

# 20. First and Last Keys

Because the map is sorted, it can efficiently identify its boundaries.

``` java
TreeMap<Integer, String> map =
        new TreeMap<>();

map.put(30, "Thirty");
map.put(10, "Ten");
map.put(20, "Twenty");

System.out.println(map.firstKey());
System.out.println(map.lastKey());
```

Output:

``` text
10
30
```

Other useful methods include:

``` java
firstEntry()
lastEntry()
```

------------------------------------------------------------------------

# 21. Keys Must Be Comparable

When using natural ordering, the key type must support meaningful
comparison.

Common Java types already do:

``` text
Integer
Long
Double
String
LocalDate
...
```

For custom objects, you normally need either:

``` text
Comparable
```

or supply:

``` text
Comparator
```

Conceptually:

``` text
TreeMap needs to answer:

"Does Key A come before,
 equal to, or after Key B?"
```

Without a valid comparison strategy, it cannot correctly maintain sorted
order.

# 22. Common Beginner Mistakes

## Mistake 1 --- Thinking TreeMap sorts values

Incorrect:

``` text
TreeMap sorts by VALUE
```

Correct:

``` text
TreeMap sorts by KEY
```

------------------------------------------------------------------------

## Mistake 2 --- Expecting insertion order

If you insert:

``` text
30
10
20
```

do not expect iteration to remain:

``` text
30
10
20
```

A natural-order `TreeMap<Integer,...>` produces:

``` text
10
20
30
```

------------------------------------------------------------------------

## Mistake 3 --- Using null as a normal natural-order key

Avoid:

``` java
map.put(null, "Value");
```

A naturally ordered `TreeMap` does not support this.

------------------------------------------------------------------------

## Mistake 4 --- Thinking a duplicate key creates another entry

``` java
map.put(1, "A");
map.put(1, "B");
```

Result:

``` text
1 → B
```

not two mappings.

------------------------------------------------------------------------

## Mistake 5 --- Assuming TreeMap is thread-safe

It is not synchronized by default.

Concurrent use requires an appropriate thread-safety strategy.

------------------------------------------------------------------------

# Final Summary

The easiest way to remember `TreeMap` is:

``` text
TreeMap
   =
Map
   +
SORTED KEYS
   +
NAVIGATION
```

Compare the three common map implementations:

``` text
HashMap
    → Fast general-purpose map
    → No guaranteed iteration order

LinkedHashMap
    → Predictable iteration order
    → Commonly insertion order

TreeMap
    → Keys automatically sorted
    → Powerful navigation methods
```

And remember the navigation rule:

``` text
lower   → <
floor   → <=

ceiling → >=
higher  → >
```

`TreeMap` is therefore a strong choice when your application needs
key-value storage **and** sorted or navigable keys.
