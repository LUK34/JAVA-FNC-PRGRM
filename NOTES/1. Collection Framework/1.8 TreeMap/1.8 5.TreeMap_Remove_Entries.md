# Java `TreeMap` --- Removing Entries

## Overview

This lesson explains how to remove entries from a Java `TreeMap`.

You will learn how to:

1.  Remove an entry using `remove(key)`.
2.  Remove an entry only when both the key and value match using
    `remove(key, value)`.
3.  Remove **and return** the first entry using `pollFirstEntry()`.
4.  Remove **and return** the last entry using `pollLastEntry()`.
5.  Understand the return values of these methods.
6.  Understand how TreeMap's **sorted key order** determines the first
    and last entries.

> **Terminology correction:** The methods are named `pollFirstEntry()`
> and `pollLastEntry()` --- not "pull first entry" or "full first
> entry." The word is **poll**.

All examples are compatible with **Java 8**.

------------------------------------------------------------------------

# 1. Create a TreeMap

Required imports:

``` java
import java.util.Map;
import java.util.NavigableMap;
import java.util.TreeMap;
```

Create the map:

``` java
NavigableMap<String, Double> productPrices =
        new TreeMap<>();
```

Add entries:

``` java
productPrices.put("Laptop", 1200.00);
productPrices.put("Smartphone", 800.00);
productPrices.put("Tablet", 500.00);
productPrices.put("Monitor", 300.00);
```

Print:

``` java
System.out.println(productPrices);
```

Because `TreeMap` sorts by key, the map appears as:

``` text
{
    Laptop=1200.0,
    Monitor=300.0,
    Smartphone=800.0,
    Tablet=500.0
}
```

The important sorted key order is:

``` text
Laptop
  ↓
Monitor
  ↓
Smartphone
  ↓
Tablet
```

# 3. Remove an Entry Using `remove(key)`

The first `remove()` form takes one argument:

``` java
remove(key)
```

Example:

``` java
productPrices.remove("Laptop");
```

Before:

``` text
Laptop     → 1200.0
Monitor    → 300.0
Smartphone → 800.0
Tablet     → 500.0
```

After:

``` text
Monitor    → 300.0
Smartphone → 800.0
Tablet     → 500.0
```

The complete mapping associated with `"Laptop"` is removed.

------------------------------------------------------------------------

# 4. `remove(key)` Removes the Mapping

It is useful to be precise about what happens.

When you write:

``` java
productPrices.remove("Laptop");
```

you are not removing only the text `"Laptop"` while leaving the price
behind.

A `Map` stores mappings:

``` text
KEY → VALUE
```

Removing the key removes its associated mapping:

``` text
Laptop → 1200.0
   |
   v
REMOVE
   |
   v
Entire mapping disappears
```

------------------------------------------------------------------------

# 5. Return Value of `remove(key)`

The one-argument version returns the value that was associated with the
removed key.

Example:

``` java
Double removedPrice =
        productPrices.remove("Laptop");

System.out.println(removedPrice);
```

Output:

``` text
1200.0
```

If the key does not exist, it normally returns:

``` text
null
```

Example:

``` java
Double removedPrice =
        productPrices.remove("Keyboard");
```

If `"Keyboard"` is absent:

``` text
removedPrice = null
```

### Important null-value detail

Since maps can contain null values, a `null` result by itself does not
always prove that the key was absent. If that distinction matters, use
`containsKey()` as well.

------------------------------------------------------------------------

# 6. Print the Map After Removal

``` java
productPrices.remove("Laptop");

System.out.println(
        "After remove(\"Laptop\"): " +
        productPrices
);
```

Result:

``` text
{Monitor=300.0, Smartphone=800.0, Tablet=500.0}
```

------------------------------------------------------------------------

# 7. Overloaded `remove(key, value)`

Java also provides another form:

``` java
remove(key, value)
```

This removes the mapping **only if**:

1.  the key exists, and
2.  that key is currently associated with the specified value.

Example:

``` java
productPrices.remove(
        "Smartphone",
        800.00
);
```

If the current mapping is:

``` text
Smartphone → 800.00
```

then it is removed.

------------------------------------------------------------------------

# 8. Why Use `remove(key, value)`?

Sometimes knowing the key alone is not enough.

You may want to say:

> Remove this mapping only if it still has the value I expect.

Conceptually:

``` text
remove("Smartphone", 800.00)
          |
          v
Does key exist?
          |
         YES
          |
          v
Does current value match 800.00?
          |
      +---+---+
      |       |
     YES      NO
      |       |
      v       v
   REMOVE   KEEP
```

------------------------------------------------------------------------

# 9. Correct Key + Correct Value

Suppose:

``` text
Smartphone → 800.0
```

Call:

``` java
boolean removed =
        productPrices.remove(
                "Smartphone",
                800.00
        );
```

Result:

``` text
removed = true
```

and the mapping disappears.

------------------------------------------------------------------------

# 10. Correct Key + Wrong Value

Suppose:

``` text
Tablet → 500.0
```

but you call:

``` java
boolean removed =
        productPrices.remove(
                "Tablet",
                50000.00
        );
```

The key exists, but the supplied value does not match.

Therefore:

``` text
removed = false
```

and the mapping remains:

``` text
Tablet → 500.0
```

------------------------------------------------------------------------

# 11. Return Value of `remove(key, value)`

The two-argument version returns a `boolean`.

``` java
boolean removed =
        productPrices.remove(
                "Tablet",
                500.00
        );
```

Possible results:

``` text
true
    → Matching mapping was removed

false
    → Mapping was not removed
```

This is different from:

``` java
remove(key)
```

which returns the previously associated value.

------------------------------------------------------------------------

# 12. Comparing the Two `remove()` Methods

  -----------------------------------------------------------------------
  Method                  Condition               Return Type
  ----------------------- ----------------------- -----------------------
  `remove(key)`           Remove mapping for key  Removed value

  `remove(key, value)`    Remove only if          `boolean`
                          key-value association   
                          matches                 
  -----------------------------------------------------------------------

Memory:

``` text
remove(KEY)
    → "Remove whatever value this key has"

remove(KEY, VALUE)
    → "Remove only if this exact association exists"
```

# 13. Example of Both `remove()` Methods

``` java
Double removedLaptop =
        productPrices.remove("Laptop");

System.out.println(
        "Removed Laptop price: " +
        removedLaptop
);

boolean removedTablet =
        productPrices.remove(
                "Tablet",
                500.00

System.out.println(
        "Was Tablet removed? " +

```

# 14. `pollFirstEntry()`

`TreeMap` implements `NavigableMap`, which provides:

``` java
pollFirstEntry()
```

This method does **two things**:

``` text
1. Finds the first entry
2. Removes it from the map
```

and then returns that removed entry.

------------------------------------------------------------------------

# 15. First Entry Means Smallest Key

Remember that TreeMap is sorted by key.

Given:

``` text
Laptop
Monitor
Smartphone
Tablet
```

the first entry is:

``` text
Laptop → 1200.0
```

Therefore:

``` java
Map.Entry<String, Double> firstEntry =
        productPrices.pollFirstEntry();
```

returns:

``` text
Laptop=1200.0
```

and removes it from the map.

------------------------------------------------------------------------

# 16. `pollFirstEntry()` Before and After

Before:

``` text
Laptop     → 1200.0
Monitor    → 300.0
Smartphone → 800.0
Tablet     → 500.0
```

Call:

``` java
Map.Entry<String, Double> firstEntry =
        productPrices.pollFirstEntry();
```

Returned:

``` text
Laptop=1200.0
```

After:

``` text
Monitor    → 300.0
Smartphone → 800.0
Tablet     → 500.0
```

So:

``` text
pollFirstEntry()
      =
RETURN first entry
      +
REMOVE first entry
```

------------------------------------------------------------------------

# 17. `firstEntry()` vs `pollFirstEntry()`

Do not confuse these methods.

### `firstEntry()`

``` java
productPrices.firstEntry();
```

returns the first entry **without removing it**.

### `pollFirstEntry()`

``` java
productPrices.pollFirstEntry();
```

returns the first entry **and removes it**.

Comparison:

  Method                 Returns First Entry   Removes It
  -------------------- --------------------- ------------
  `firstEntry()`                         Yes           No
  `pollFirstEntry()`                     Yes          Yes

Memory:

``` text
firstEntry()
    → LOOK

pollFirstEntry()
    → TAKE OUT
```

------------------------------------------------------------------------

# 18. `pollLastEntry()`

Similarly, `NavigableMap` provides:

``` java
pollLastEntry()
```

It:

``` text
1. Finds the last entry
2. Removes it
3. Returns the removed entry
```

------------------------------------------------------------------------

# 19. Last Entry Means Greatest Key

Given:

``` text
Laptop
Monitor
Smartphone
Tablet
```

the greatest/last key is:

``` text
Tablet
```

So:

``` java
Map.Entry<String, Double> lastEntry =
        productPrices.pollLastEntry();
```

returns:

``` text
Tablet=500.0
```

and removes that mapping.

# 23. Empty TreeMap Behavior

What happens if the map is empty?

``` java
NavigableMap<String, Double> map =
        new TreeMap<>();
```

Then:

``` java
map.pollFirstEntry();
```

returns:

``` text
null
```

and:

``` java
map.pollLastEntry();
```

also returns:

``` text
null
```

So you can safely check:

``` java
Map.Entry<String, Double> entry =
        map.pollFirstEntry();

if (entry != null) {

```

# 24. Complete Runnable Example

``` java
import java.util.Map;
import java.util.NavigableMap;
import java.util.TreeMap;

public class RemoveEntriesFromTreeMapExample {

    public static void main(String[] args) {

        NavigableMap<String, Double> productPrices =
                new TreeMap<>();

        productPrices.put("Laptop", 1200.00);
        productPrices.put("Smartphone", 800.00);
        productPrices.put("Tablet", 500.00);
        productPrices.put("Monitor", 300.00);

        System.out.println(
                "Original TreeMap: " +
                productPrices
        );

        // --------------------------------
        // 1. remove(key)
        // --------------------------------

        Double removedValue =
                productPrices.remove("Laptop");

        System.out.println(
                "\nRemoved Laptop value: " +
                removedValue
        );

        System.out.println(
                "After remove(key): " +
                productPrices
        );

        // --------------------------------
        // 2. remove(key, value)
        // --------------------------------

        boolean removed =
                productPrices.remove(
                        "Tablet",
                        50000.00
                );

        System.out.println(
                "\nWas Tablet removed with " +
                "wrong value? " +
                removed
        );

        System.out.println(
                "After wrong key-value remove: " +
                productPrices
        );

        removed =
                productPrices.remove(
                        "Tablet",
                        500.00
                );

        System.out.println(
                "\nWas Tablet removed with " +
                "correct value? " +
                removed
        );

        System.out.println(
                "After correct key-value remove: " +
                productPrices
        );

        // --------------------------------
        // Reset map for poll examples
        // --------------------------------

        productPrices.clear();

        productPrices.put("Laptop", 1200.00);
        productPrices.put("Smartphone", 800.00);
        productPrices.put("Tablet", 500.00);
        productPrices.put("Monitor", 300.00);

        System.out.println(
                "\nReset TreeMap: " +
                productPrices
        );

        // --------------------------------
        // 3. pollFirstEntry()
        // --------------------------------

        Map.Entry<String, Double> firstEntry =
                productPrices.pollFirstEntry();

        System.out.println(
                "\nRemoved first entry: " +
                firstEntry
        );

        System.out.println(
                "After pollFirstEntry(): " +
                productPrices
        );

        // --------------------------------
        // 4. pollLastEntry()
        // --------------------------------

        Map.Entry<String, Double> lastEntry =
                productPrices.pollLastEntry();

        System.out.println(
                "\nRemoved last entry: " +
                lastEntry
        );

        System.out.println(
                "After pollLastEntry(): " +
                productPrices
        );
    }
}
```

# 27. Why Does TreeMap Order Matter Here?

The terms:

``` text
FIRST
```

and:

``` text
LAST
```

refer to the TreeMap's **key ordering**.

They do not refer to insertion time.

Given insertion:

``` text
Laptop
Smartphone
Tablet
Monitor
```

natural String sorting produces:

``` text
Laptop
Monitor
Smartphone
Tablet
```

Therefore:

``` text
pollFirstEntry()
      ↓
Laptop
```

and:

``` text
pollLastEntry()
      ↓
Tablet
```

------------------------------------------------------------------------

# 28. What If a Custom Comparator Is Used?

Suppose you create:

``` java
NavigableMap<String, Double> productPrices =
        new TreeMap<>(
                java.util.Comparator.reverseOrder()
        );
```

Now the ordering becomes approximately:

``` text
Tablet
Smartphone
Monitor
Laptop
```

Therefore:

``` java
pollFirstEntry();
```

would remove:

``` text
Tablet
```

while:

``` java
pollLastEntry();
```

would remove:

``` text
Laptop
```

So remember:

``` text
FIRST / LAST
      ↓
Determined by TreeMap ordering
      ↓
Natural order OR Comparator
```

# 29. Common Beginner Mistakes

## Mistake 1 --- Calling the method `pullFirstEntry()`

Incorrect:

``` java
pullFirstEntry()
```

Correct:

``` java
pollFirstEntry()
```

Likewise:

``` java
pollLastEntry()
```

The word is **poll**.

------------------------------------------------------------------------

## Mistake 2 --- Thinking `remove(key)` removes only the key

It removes the entire mapping:

``` text
KEY + associated VALUE
```

------------------------------------------------------------------------

## Mistake 3 --- Supplying the wrong value to `remove(key, value)`

If:

``` text
Tablet → 500.0
```

then:

``` java
remove("Tablet", 50000.0)
```

does not remove it.

------------------------------------------------------------------------

## Mistake 4 --- Ignoring the boolean result

For:

``` java
remove(key, value)
```

the returned boolean tells you whether removal actually happened.

Use it:

``` java
boolean removed =
        map.remove(key, value);
```

------------------------------------------------------------------------

## Mistake 5 --- Thinking `pollFirstEntry()` only retrieves

It modifies the map.

``` text
pollFirstEntry()
    → RETURN + REMOVE
```

------------------------------------------------------------------------

## Mistake 6 --- Thinking first means first inserted

For `TreeMap`:

``` text
FIRST
   =
Smallest key according to map ordering
```

not the first inserted key.

------------------------------------------------------------------------

# 30. Quick Cheat Sheet

Remove by key:

``` java
V removedValue =
        map.remove(key);
```

Remove only when key and value match:

``` java
boolean removed =
        map.remove(key, value);
```

Remove and return first entry:

``` java
Map.Entry<K, V> first =
        map.pollFirstEntry();
```

Remove and return last entry:

``` java
Map.Entry<K, V> last =
        map.pollLastEntry();
```

Retrieve first without removal:

``` java
Map.Entry<K, V> first =
        map.firstEntry();
```

Retrieve last without removal:

``` java
Map.Entry<K, V> last =
        map.lastEntry();
```

# 31. Interview / Exam Points

1.  `remove(key)` removes the mapping associated with a key.
2.  `remove(key)` returns the previously associated value.
3.  `remove(key, value)` removes only if the current association
    matches.
4.  `remove(key, value)` returns `true` when removal succeeds.
5.  `remove(key, value)` returns `false` when the association does not
    match.
6.  `pollFirstEntry()` removes and returns the first entry.
7.  `pollLastEntry()` removes and returns the last entry.
8.  `firstEntry()` retrieves without removing.
9.  `lastEntry()` retrieves without removing.
10. `pollFirstEntry()` and `pollLastEntry()` return `null` when the map
    is empty.
11. TreeMap's first entry is determined by the smallest key according to
    its ordering.
12. TreeMap's last entry is determined by the greatest key according to
    its ordering.
13. A custom comparator changes what counts as first and last.
14. `pollFirstEntry()` and `pollLastEntry()` come from the
    `NavigableMap` API.
15. The correct method name is **poll**, not pull.

``` text
                    TreeMap
                       |
        +--------------+--------------+
        |              |              |
        v              v              v
   remove(key)   remove(key,value)   poll...
        |              |              |
```

Difference between lookup and removal:

``` text
firstEntry()
    → READ first

pollFirstEntry()
    → READ + REMOVE first


lastEntry()
    → READ last

pollLastEntry()
    → READ + REMOVE last
```

# Final Summary

The four key removal operations from this lesson are:

``` java
remove(key)
```

``` java
remove(key, value)
```

``` java
pollFirstEntry()
```

``` java
pollLastEntry()
```

The easiest memory rule is:

``` text
remove(KEY)
    → Remove by key

remove(KEY, VALUE)
    → Remove only if association matches

pollFirstEntry()
    → Remove + return FIRST

pollLastEntry()
    → Remove + return LAST
```

And always remember:

``` text
TreeMap FIRST and LAST
        ↓
Based on SORTED KEY ORDER
        ↓
Not insertion order
```

This makes `pollFirstEntry()` and `pollLastEntry()` particularly useful
when you need to consume entries from either end of an ordered map.
