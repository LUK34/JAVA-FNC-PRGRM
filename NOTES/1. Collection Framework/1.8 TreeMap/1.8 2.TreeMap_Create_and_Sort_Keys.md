# Java `TreeMap` --- Creating Maps and Sorting Keys

## Overview

This lesson explains how to create a Java `TreeMap` and control the
ordering of its keys.

You will learn how to:

1.  Create a basic `TreeMap`.
2.  Add key-value pairs using `put()`.
3.  Understand the default natural ordering of keys.
4.  Sort keys in descending order with a custom `Comparator`.
5.  Create a case-insensitive `TreeMap`.
6.  Understand an important consequence of comparators: **comparison
    determines key uniqueness in a `TreeMap`**.

All examples are compatible with **Java 8**.

------------------------------------------------------------------------

# 1. What Does TreeMap Do?

A `TreeMap` stores data as:

``` text
KEY → VALUE
```

and automatically maintains its keys according to a sorting rule.

For example:

``` text
Inserted:

Python → .py
C++    → .cpp
Kotlin → .kt
Golang → .go
Java   → .java
```

A naturally ordered `TreeMap<String, String>` iterates in key order:

``` text
C++
Golang
Java
Kotlin
Python
```

So unlike a normal `HashMap`, the ordering is meaningful and
predictable.

``` text

          │       └── VALUE type

      │
      └── Actual implementation object
```

# 4. Add Key-Value Pairs

Use `put()`:

``` java
fileExtensions.put("Python", ".py");
fileExtensions.put("C++", ".cpp");
fileExtensions.put("Kotlin", ".kt");
fileExtensions.put("Golang", ".go");
fileExtensions.put("Java", ".java");
```

The logical data is:

  Language   Extension
  ---------- -----------
  Python     `.py`
  C++        `.cpp`
  Kotlin     `.kt`
  Golang     `.go`
  Java       `.java`

# 5. Print the TreeMap

``` java
System.out.println(fileExtensions);
```

Typical output:

``` text
{C++=.cpp, Golang=.go, Java=.java, Kotlin=.kt, Python=.py}
```

Notice that this is **not insertion order**.

The keys are ordered according to the natural ordering of `String`.

# 6. Natural Ordering

When you create:

``` java
new TreeMap<>()
```

without supplying a comparator, `TreeMap` uses the keys' natural
ordering.

For integers:

``` text
30
10
20

     ↓ TreeMap

10
20
30
```

For strings:

``` text
Python
C++
Kotlin
Golang
Java

     ↓ TreeMap

C++
Golang
Java
Kotlin
Python
```

For `String`, natural ordering is based on `String.compareTo()` and is
lexicographical and case-sensitive.

------------------------------------------------------------------------

# 7. Complete Natural-Order Example

``` java
import java.util.SortedMap;
import java.util.TreeMap;

public class CreateTreeMapExample {

    public static void main(String[] args) {

        SortedMap<String, String> fileExtensions =
                new TreeMap<>();

        fileExtensions.put("Python", ".py");
        fileExtensions.put("C++", ".cpp");
        fileExtensions.put("Kotlin", ".kt");
        fileExtensions.put("Golang", ".go");
        fileExtensions.put("Java", ".java");

        System.out.println(fileExtensions);
    }
}
```

Output:

``` text
{C++=.cpp, Golang=.go, Java=.java, Kotlin=.kt, Python=.py}
```

# 8. TreeMap with Descending Key Order

Sometimes natural ascending order is not what you want.

For example, instead of:

``` text
C++
Golang
Java
Kotlin
Python
```

you may want:

``` text
Python
Kotlin
Java
Golang
C++
```

For this, provide a comparator when creating the `TreeMap`.

# 9. `Comparator.reverseOrder()`

Java provides:

``` java
Comparator.reverseOrder()
```

``` java
SortedMap<String, String> fileExtensions =

```

Then add the entries:

``` java
fileExtensions.put("Python", ".py");
fileExtensions.put("C++", ".cpp");
fileExtensions.put("Kotlin", ".kt");
fileExtensions.put("Golang", ".go");
fileExtensions.put("Java", ".java");
```

Print:

``` java
System.out.println(fileExtensions);
```

Typical output:

``` text
{Python=.py, Kotlin=.kt, Java=.java, Golang=.go, C++=.cpp}
```

# 10. Natural vs Reverse Order

``` text
Natural ordering:

C++
 ↓
Golang
 ↓
Java
 ↓
Kotlin
 ↓
Python
```

Using:

``` java
Comparator.reverseOrder()
```

produces:

``` text

 ↓
Kotlin
 ↓

 ↓

 ↓

```

# 11. Complete Reverse-Order Example

``` java
import java.util.Comparator;

        fileExtensions.put("Python", ".py");
        fileExtensions.put("C++", ".cpp");
        fileExtensions.put("Kotlin", ".kt");
        fileExtensions.put("Golang", ".go");
        fileExtensions.put("Java", ".java");

        System.out.println(fileExtensions);
    }
}
```

# 12. TreeMap String Keys Are Normally Case-Sensitive

Consider:

``` java
TreeMap<String, String> map =
        new TreeMap<>();

map.put("python", ".py");
map.put("Python", ".PY");
```

With normal `String` natural ordering:

``` text
"python"
```

and:

``` text
"Python"
```

are different keys.

Why?

Because:

``` java
"python".compareTo("Python")
```

does not return `0`.

Therefore a naturally ordered `TreeMap` can contain both mappings.

------------------------------------------------------------------------

# 13. Case-Insensitive TreeMap

Java provides a useful comparator:

``` java
String.CASE_INSENSITIVE_ORDER
```

Create the map like this:

``` java
SortedMap<String, String> fileExtensions =
        new TreeMap<>(
                String.CASE_INSENSITIVE_ORDER
        );
```

Now key comparison ignores case.

For example:

``` java
fileExtensions.put("python", ".py");
fileExtensions.put("Python", ".PY");
```

The comparator treats these keys as equivalent for map ordering:

``` text
python
Python
   ↓
compare as equal
```

Therefore they cannot exist as two separate TreeMap keys under this
comparator.

------------------------------------------------------------------------

# 14. Very Important: Comparator Determines Key Uniqueness

This is one of the most important concepts in this lecture.

For a `TreeMap`, two keys are treated as the same map key when the map's
comparison mechanism returns:

``` text
0
```

With:

``` java
String.CASE_INSENSITIVE_ORDER
```

comparison of:

``` text
"python"
"Python"
```

returns `0`.

So when you execute:

``` java
map.put("python", ".py");
map.put("Python", ".PY");
```

the second `put()` **replaces the value associated with the existing
comparator-equivalent key** rather than creating a second entry.

This is more precise than saying the duplicate is simply "ignored."

------------------------------------------------------------------------

# 15. Which Key Object Is Displayed?

This subtle behavior is useful to understand.

Example:

``` java
TreeMap<String, String> map =
        new TreeMap<>(
                String.CASE_INSENSITIVE_ORDER
        );

map.put("python", ".py");
map.put("Python", ".PY");

System.out.println(map);
```

The existing mapping's value is replaced because the comparator says the
keys are equivalent.

Typically, the original stored key object remains while its associated
value changes.

So output can be:

``` text
{python=.PY}
```

not necessarily:

``` text
{Python=.PY}
```

The key point is:

``` text
Comparator says compare(...) == 0
             ↓
Same TreeMap key position
             ↓
New value replaces old value
```

------------------------------------------------------------------------

# 16. Complete Case-Insensitive Example

``` java
import java.util.SortedMap;
import java.util.TreeMap;

public class CreateTreeMapCaseInsensitiveOrderExample {

    public static void main(String[] args) {

        SortedMap<String, String> fileExtensions =
                new TreeMap<>(
                        String.CASE_INSENSITIVE_ORDER
                );

        fileExtensions.put("python", ".py");
        fileExtensions.put("C++", ".cpp");
        fileExtensions.put("Kotlin", ".kt");
        fileExtensions.put("Golang", ".go");
        fileExtensions.put("Java", ".java");

        // Comparator considers this equivalent
        // to the existing "python" key.
        fileExtensions.put("Python", ".PY");

        System.out.println(fileExtensions);
    }
}
```

The map contains only one comparator-equivalent Python key mapping.

# 20. Why Use `SortedMap` as the Reference?

The lecture uses:

``` java
SortedMap<String, String> fileExtensions =
        new TreeMap<>();
```

rather than:

``` java
TreeMap<String, String> fileExtensions =
        new TreeMap<>();
```

Both are valid.

Using the interface type is often good design:

``` text
Reference type
    ↓
SortedMap

Implementation
    ↓
TreeMap
```

It reduces unnecessary coupling to the concrete implementation.

However, if you specifically need methods declared by `NavigableMap` or
`TreeMap` but not by `SortedMap`, choose an appropriate reference type
such as:

``` java
NavigableMap<K,V>
```

or:

``` java
TreeMap<K,V>
```

------------------------------------------------------------------------

# 21. What Happens with Duplicate Keys?

Normal map:

``` java
map.put("Java", ".java");
map.put("Java", ".class");
```

Result:

``` text
Java → .class
```

The second value replaces the first.

With a comparator, the same principle applies to keys that compare as
equal.

For example:

``` java
TreeMap<String, Integer> map =
        new TreeMap<>(
                String.CASE_INSENSITIVE_ORDER
        );

map.put("JAVA", 1);
map.put("java", 2);
```

The comparator considers:

``` text
JAVA == java
```

for ordering/key-equivalence purposes.

So there is only one mapping, with the later value.

------------------------------------------------------------------------

# 22. Comparator Concept

A comparator conceptually answers:

``` text
Compare Key A with Key B
          |
          v
      What result?
```

If the result is:

``` text
Negative
    → A comes before B

Zero
    → A and B are equivalent
      for TreeMap key ordering

Positive
    → A comes after B
```

This comparison drives both:

``` text
SORTING
   +
KEY EQUIVALENCE
```

inside a `TreeMap`.

------------------------------------------------------------------------

# 23. TreeMap vs LinkedHashMap

This is especially important after learning `LinkedHashMap`.

Suppose insertion is:

``` text
Python
C++
Kotlin
Golang
Java
```

### LinkedHashMap

Default iteration order:

``` text
Python
C++
Kotlin
Golang
Java
```

because it preserves insertion order.

### TreeMap

Natural-order iteration:

``` text
C++
Golang
Java
Kotlin
Python
```

because it sorts by key.

Memory rule:

``` text
LinkedHashMap
    → insertion/predictable order

TreeMap
    → sorted key order
```

# 24. TreeMap with Integer Keys

Natural ordering also applies to numbers.

``` java
SortedMap<Integer, String> map =
        new TreeMap<>();

map.put(50, "Fifty");
map.put(10, "Ten");
map.put(30, "Thirty");
map.put(20, "Twenty");
```

Output:

``` text
{10=Ten, 20=Twenty, 30=Thirty, 50=Fifty}
```

So:

``` text
String keys
    → natural String order

Integer keys
    → ascending numeric order
```

unless a custom comparator changes that behavior.

# 26. Common Beginner Mistakes

## Mistake 1 --- Expecting insertion order

Given:

``` java
map.put("Python", ".py");
map.put("C++", ".cpp");
map.put("Java", ".java");
```

a `TreeMap` does not preserve that sequence as its normal iteration
order.

It sorts the keys.

------------------------------------------------------------------------

## Mistake 2 --- Thinking TreeMap sorts values

`TreeMap` sorts:

``` text
KEYS
```

not:

``` text
VALUES
```

------------------------------------------------------------------------

## Mistake 3 --- Thinking a comparator only changes display order

A comparator does more than determine how entries appear.

It also determines when two keys are equivalent for the purposes of the
`TreeMap`.

If:

``` java
comparator.compare(key1, key2) == 0
```

the map treats them as the same key position.

------------------------------------------------------------------------

## Mistake 4 --- Saying case-insensitive duplicates are simply ignored

More accurately:

``` text
Existing equivalent key
        +
new put()
        ↓
Value is replaced
```

The new mapping does not become an additional entry.

------------------------------------------------------------------------

## Mistake 5 --- Confusing `Comparator.reverseOrder()` with `Collections.reverseOrder()`

Both utilities can be used in relevant contexts, but this lecture uses:

``` java
Comparator.reverseOrder()
```

which directly returns a reverse-natural-order comparator.

------------------------------------------------------------------------

# 27. Complete Demonstration

``` java
import java.util.Comparator;
import java.util.SortedMap;
import java.util.TreeMap;

public class TreeMapSortingDemo {

    public static void main(String[] args) {

        // ----------------------------------
        // 1. Natural ordering
        // ----------------------------------

        SortedMap<String, String> natural =
                new TreeMap<>();

        natural.put("Python", ".py");
        natural.put("C++", ".cpp");
        natural.put("Kotlin", ".kt");
        natural.put("Golang", ".go");
        natural.put("Java", ".java");

        System.out.println(
                "Natural Order:"
        );

        System.out.println(natural);

        // ----------------------------------
        // 2. Reverse ordering
        // ----------------------------------

        SortedMap<String, String> reverse =
                new TreeMap<>(
                        Comparator.reverseOrder()
                );

        reverse.putAll(natural);

        System.out.println(
                "\nReverse Order:"
        );

        System.out.println(reverse);

        // ----------------------------------
        // 3. Case-insensitive ordering
        // ----------------------------------

        SortedMap<String, String> caseInsensitive =
                new TreeMap<>(
                        String.CASE_INSENSITIVE_ORDER
                );

        caseInsensitive.put("python", ".py");
        caseInsensitive.put("Java", ".java");

        // Replaces the value associated with
        // the comparator-equivalent "python" key.
        caseInsensitive.put("Python", ".PY");

        System.out.println(
                "\nCase-Insensitive:"
        );

        System.out.println(caseInsensitive);
    }
}
```

# 29. Interview / Exam Points

1.  `TreeMap` automatically maintains its keys in sorted order.
2.  Without a comparator, it uses natural key ordering.
3.  `String` natural ordering is case-sensitive and lexicographical.
4.  Numeric wrapper types such as `Integer` naturally sort numerically.
5.  A custom `Comparator` can change the ordering.
6.  `Comparator.reverseOrder()` provides reverse natural ordering.
7.  `String.CASE_INSENSITIVE_ORDER` compares strings without considering
    case.
8.  TreeMap key uniqueness is determined by its comparison mechanism.
9.  If comparison returns `0`, the keys are treated as equivalent by the
    `TreeMap`.
10. Putting a comparator-equivalent key replaces the existing mapping's
    value.
11. `TreeMap` sorts keys, not values.
12. `SortedMap` can be used as the reference type for a `TreeMap`.
13. `LinkedHashMap` and `TreeMap` solve different ordering requirements:
    insertion-oriented vs sorted-key ordering.

The three important creation patterns from this lecture are:

``` java

```


Easy memory:

``` text
TreeMap
   |

   |
```

``` text
Sorting Rule
        +
```
