# Java `TreeMap` --- Iterating Over Entries, Keys, and Values

## Overview

This lesson explains several common ways to iterate over a Java
`TreeMap`.

You will learn how to:

1.  Iterate over all key-value pairs using Java 8 `forEach()` and a
    lambda expression.
2.  Iterate over `entrySet()` using an explicit `Iterator`.
3.  Iterate over `keySet()` to access only keys.
4.  Iterate over `values()` to access only values.
5.  Understand `BiConsumer`, `Map.Entry`, `Iterator`, `hasNext()`, and
    `next()`.
6.  Understand why TreeMap iteration follows **sorted key order**.

All examples are compatible with **Java 8**.

------------------------------------------------------------------------

# 1. Create a TreeMap

Required imports:

``` java
import java.util.Iterator;
import java.util.Map;
import java.util.NavigableMap;
import java.util.TreeMap;
```

Create the map:

``` java
NavigableMap<String, Double> productPrices =
        new TreeMap<>();
```

Add some products:

``` java
productPrices.put("Laptop", 1200.00);
productPrices.put("Smartphone", 800.00);
productPrices.put("Tablet", 500.00);
productPrices.put("Monitor", 300.00);
```

------------------------------------------------------------------------

# 2. TreeMap Iteration Order

The insertion order above was:

``` text
Laptop
Smartphone
Tablet
Monitor
```

But a naturally ordered `TreeMap<String, ...>` iterates according to its
sorted key order:

``` text
Laptop
Monitor
Smartphone
Tablet
```

So printing:

``` java
System.out.println(productPrices);
```

typically gives:

``` text
{Laptop=1200.0, Monitor=300.0, Smartphone=800.0, Tablet=500.0}
```

This is important for every iteration technique in this lesson.

``` text
TreeMap iteration
       ↓
TreeMap's key ordering
       ↓
Natural ordering OR custom Comparator
```

# 3. Four Main Iteration Approaches

This lecture covers:

``` text
TreeMap
│
├── 1. Map.forEach()
│       └── Key + Value
│
├── 2. entrySet() + Iterator
│       └── Key + Value through Map.Entry
│
├── 3. keySet()
│       └── Keys only
│
└── 4. values()
        └── Values only
```

# 4. Approach 1 --- Java 8 `forEach()` + Lambda

A `Map` provides the Java 8 `forEach()` method.

Example:

``` java
productPrices.forEach(
        (key, value) -> {
            System.out.println(
                    key + " -> " + value
            );
        }
);
```

Output:

``` text
Laptop -> 1200.0
Monitor -> 300.0
Smartphone -> 800.0
Tablet -> 500.0
```

------------------------------------------------------------------------

# 5. Understanding the Lambda

This:

``` java
(key, value) -> {
    System.out.println(
            key + " -> " + value
    );
}
```

means:

``` text
For every map entry
        |
        +── key
        |
        └── value
             |
             v
Execute the lambda body
```

For the first entry:

``` text
key   = Laptop
value = 1200.0
```

For the next:

``` text
key   = Monitor
value = 300.0
```

and so on.

------------------------------------------------------------------------

# 6. Why Does `Map.forEach()` Use `BiConsumer`?

The `Map.forEach()` method accepts a:

``` java
BiConsumer
```

A `BiConsumer` consumes **two input values**.

For a map:

``` text
Input 1 → KEY
Input 2 → VALUE
```

Conceptually:

``` java
BiConsumer<K, V>
```

For our map:

``` java
BiConsumer<String, Double>
```

The lambda:

``` java
(key, value) -> ...
```

provides the implementation of that functional interface.

------------------------------------------------------------------------

# 7. Shorter Lambda Syntax

If the lambda contains only one statement, braces can be omitted:

``` java
productPrices.forEach(
        (key, value) ->
                System.out.println(
                        key + " -> " + value
                )
);
```

Both versions are valid.

### With braces

``` java
(key, value) -> {
    System.out.println(key + " -> " + value);
}
```

### Without braces

``` java
(key, value) ->
        System.out.println(key + " -> " + value)
```

------------------------------------------------------------------------

# 8. When Is `Map.forEach()` Useful?

Use:

``` java
map.forEach((key, value) -> ...)
```

when you need both:

``` text
KEY + VALUE
```

and want concise Java 8 code.

For example:

``` java
productPrices.forEach(
        (product, price) ->
                System.out.println(
                        product +
                        " costs " +
                        price
                )
);
```

------------------------------------------------------------------------

# 9. Approach 2 --- `entrySet()` + `Iterator`

The second approach uses:

``` java
entrySet()
```

followed by:

``` java
iterator()
```

Start with:

``` java
Iterator<Map.Entry<String, Double>>
        entryIterator =
        productPrices.entrySet().iterator();
```

This may look complicated initially, so break it down.

# 10. Understanding `entrySet()`

A map contains entries:

``` text
Laptop     → 1200.0
Monitor    → 300.0
Smartphone → 800.0
Tablet     → 500.0
```

Each individual mapping can be represented by:

``` java
Map.Entry<String, Double>
```

Calling:

``` java
productPrices.entrySet()
```

gives a set-like view of all those entries.

Conceptually:

``` text
entrySet()

{
    Laptop=1200.0,
    Monitor=300.0,
    Smartphone=800.0,
    Tablet=500.0
}
```

------------------------------------------------------------------------

# 11. Understanding `Map.Entry`

For:

``` java
Map.Entry<String, Double> entry;
```

you can access:

``` java
entry.getKey();
entry.getValue();
```

Example:

``` text
Entry:
Laptop=1200.0

entry.getKey()
       ↓
Laptop

entry.getValue()
       ↓
1200.0
```

------------------------------------------------------------------------

# 12. Get the Iterator

Call:

``` java
productPrices.entrySet().iterator();
```

Store it:

``` java
Iterator<Map.Entry<String, Double>>
        entryIterator =
        productPrices.entrySet().iterator();
```

The iterator lets us move through the entries one at a time.

------------------------------------------------------------------------

# 13. Iterate with `while`

Use:

``` java
while (entryIterator.hasNext()) {

    Map.Entry<String, Double> entry =
            entryIterator.next();

    System.out.println(
            entry.getKey() +
            " -> " +
            entry.getValue()
    );
}
```

------------------------------------------------------------------------

# 14. `hasNext()` and `next()`

These two methods are fundamental to `Iterator`.

### `hasNext()`

``` java
entryIterator.hasNext()
```

asks:

``` text
"Is another entry available?"
```

Returns:

``` text
true
```

or:

``` text
false
```

### `next()`

``` java
entryIterator.next()
```

returns the next entry and advances the iterator.

------------------------------------------------------------------------

# 15. Iterator Flow

``` text
Create Iterator
      |
      v
hasNext()?
   |
   +── false ──→ STOP
   |
   └── true
         |
         v
       next()
         |
         v
   Get Map.Entry
         |
         v
 getKey()/getValue()
         |
         v
    Repeat loop
```

This pattern is worth memorizing:

``` java
while (iterator.hasNext()) {
    Object value = iterator.next();
}
```

------------------------------------------------------------------------

# 16. Why Use an Explicit Iterator?

An explicit iterator is more verbose than `forEach()`, but it provides
direct control over traversal.

It is especially useful when:

-   you are learning how collection traversal works;
-   you need iterator-specific behavior;
-   you may need safe iterator-based removal where supported.

For simple read-only traversal, Java 8 `forEach()` or an enhanced `for`
loop is often easier to read.

------------------------------------------------------------------------

# 17. Approach 3 --- Iterate Over `keySet()`

Sometimes you need only the keys.

Use:

``` java
productPrices.keySet();
```

The result represents all keys in the map.

For our example:

``` text
Laptop
Monitor
Smartphone
Tablet
```

Iterate using the enhanced `for` loop:

``` java
for (String product : productPrices.keySet()) {

    System.out.println(
            "Product: " + product
    );
}
```

------------------------------------------------------------------------

# 18. Why Does `keySet()` Return a Set?

Map keys must be unique.

You cannot have two independent mappings with exactly the same key.

Therefore:

``` java
keySet()
```

returns a:

``` java
Set<K>
```

Conceptually:

``` text
Map<String, Double>
        |
        v
keySet()
        |
        v
Set<String>
```

------------------------------------------------------------------------

# 19. Access a Value While Iterating Keys

If you are iterating keys and also need the corresponding value, you
*can* write:

``` java
for (String product : productPrices.keySet()) {

    Double price =
            productPrices.get(product);

    System.out.println(
            product + " -> " + price
    );
}
```

However, if you need **both key and value for every entry**,
`entrySet()` or `Map.forEach()` is generally the more direct approach.

Use:

``` text
keySet()
```

primarily when the keys themselves are what you need.

------------------------------------------------------------------------

# 20. Approach 4 --- Iterate Over `values()`

Sometimes you need only the values.

Use:

``` java
productPrices.values();
```

For our map, the values are encountered in the order corresponding to
the map's key iteration order:

``` text
1200.0
300.0
800.0
500.0
```

Iterate:

``` java
for (Double price : productPrices.values()) {

    System.out.println(
            "Price: " + price
    );
}
```

------------------------------------------------------------------------

# 21. Why Does `values()` Return a Collection?

Map values do not have to be unique.

For example:

``` java
productPrices.put("Laptop", 500.00);
productPrices.put("Tablet", 500.00);
```

This is valid.

So:

``` java
values()
```

returns a:

``` java
Collection<V>
```

rather than a `Set<V>`.

Conceptually:

``` text
Keys
    → Unique
    → Set<K>

Values
    → May contain duplicates
    → Collection<V>
```

------------------------------------------------------------------------

# 22. `entrySet()` vs `keySet()` vs `values()`

  Method         What You Get   Typical Use
  -------------- -------------- ------------------
  `entrySet()`   Key + Value    Need both
  `keySet()`     Keys           Need only keys
  `values()`     Values         Need only values

Easy memory:

``` text
entrySet()
    → ENTRY
    → KEY + VALUE

keySet()
    → KEY

values()
    → VALUE
```

------------------------------------------------------------------------

# 23. Complete Runnable Example

``` java
import java.util.Iterator;
import java.util.Map;
import java.util.NavigableMap;
import java.util.TreeMap;

public class IterateOverTreeMapExample {

    public static void main(String[] args) {

        NavigableMap<String, Double> productPrices =
                new TreeMap<>();

        productPrices.put("Laptop", 1200.00);
        productPrices.put("Smartphone", 800.00);
        productPrices.put("Tablet", 500.00);
        productPrices.put("Monitor", 300.00);

        System.out.println(
                "TreeMap: " + productPrices
        );

        // ------------------------------------
        // 1. Java 8 forEach + lambda
        // ------------------------------------

        System.out.println(
                "\n1. Map.forEach() + Lambda"
        );

        productPrices.forEach(
                (key, value) ->
                        System.out.println(
                                key +
                                " -> " +
                                value
                        )
        );

        // ------------------------------------
        // 2. entrySet() + Iterator
        // ------------------------------------

        System.out.println(
                "\n2. entrySet() + Iterator"
        );

        Iterator<Map.Entry<String, Double>>
                entryIterator =
                productPrices
                        .entrySet()
                        .iterator();

        while (entryIterator.hasNext()) {

            Map.Entry<String, Double> entry =
                    entryIterator.next();

            System.out.println(
                    entry.getKey() +
                    " -> " +
                    entry.getValue()
            );
        }

        // ------------------------------------
        // 3. keySet()
        // ------------------------------------

        System.out.println(
                "\n3. keySet() - Keys Only"
        );

        for (String product :
                productPrices.keySet()) {

            System.out.println(
                    "Product: " + product
            );
        }

        // ------------------------------------
        // 4. values()
        // ------------------------------------

        System.out.println(
                "\n4. values() - Values Only"
        );

        for (Double price :
                productPrices.values()) {

            System.out.println(
                    "Price: " + price
            );
        }
    }
}
```

# 25. Another Useful Approach --- Enhanced `for` with `entrySet()`

Although the lecture demonstrates an explicit iterator for `entrySet()`,
a very common Java style is:

``` java
for (Map.Entry<String, Double> entry :
        productPrices.entrySet()) {

    System.out.println(
            entry.getKey() +
            " -> " +
            entry.getValue()
    );
}
```

This is often easier to read than manually managing an iterator.

Use it when:

``` text
Need both key and value
+
Do not need explicit Iterator control
```

------------------------------------------------------------------------

# 26. Java 8 `entrySet().forEach()`

You can also combine `entrySet()` with Java 8 `forEach()`:

``` java
productPrices
        .entrySet()
        .forEach(entry ->
                System.out.println(
                        entry.getKey() +
                        " -> " +
                        entry.getValue()
                )
        );
```

Here the lambda receives:

``` text
ONE object
    ↓
Map.Entry
```

Compare that with:

``` java
productPrices.forEach(
        (key, value) -> ...
);
```

which directly receives:

``` text
TWO values
   ↓
KEY + VALUE
```

------------------------------------------------------------------------

# 27. `BiConsumer` vs `Consumer`

This distinction helps explain the two Java 8 styles.

### `Map.forEach()`

``` java
productPrices.forEach(
        (key, value) -> ...
);
```

Conceptually uses:

``` text
BiConsumer<K,V>
```

because the lambda receives:

``` text
KEY + VALUE
```

### `entrySet().forEach()`

``` java
productPrices.entrySet().forEach(
        entry -> ...
);
```

Conceptually uses a:

``` text
Consumer<Map.Entry<K,V>>
```

because the lambda receives one entry object.

Memory:

``` text
BiConsumer
    → TWO inputs

Consumer
    → ONE input
```

# 28. Choosing the Right Iteration Method

Use this guide:

``` text
What do you need?
       |
       +── Key + Value
       |      |
       |      +── Simple Java 8 code
       |      |      → Map.forEach()
       |      |
       |      +── Entry object
       |      |      → entrySet()
       |      |
       |      └── Explicit traversal control
       |             → entrySet().iterator()
       |
       +── Keys only
       |      → keySet()
       |
       └── Values only
              → values()
```

# 29. Important TreeMap Difference

The iteration techniques themselves are familiar from other `Map`
implementations.

The major `TreeMap` difference is **ordering**.

### HashMap

``` text
No guaranteed iteration order
```

### LinkedHashMap

``` text
Predictable order,
commonly insertion order
```

### TreeMap

``` text
Sorted key order
```

So:

``` java
for (String key : treeMap.keySet()) {
    ...
}
```

iterates according to the `TreeMap`'s key ordering.

------------------------------------------------------------------------

# 30. Custom Comparator Also Affects Iteration

Suppose:

``` java
TreeMap<String, Double> productPrices =
        new TreeMap<>(
                java.util.Comparator.reverseOrder()
        );
```

Now iteration follows reverse key order.

Instead of:

``` text
Laptop
Monitor
Smartphone
Tablet
```

you would get:

``` text
Tablet
Smartphone
Monitor
Laptop
```

Therefore:

``` text
TreeMap iteration order
        =
TreeMap comparator/order
```

# 31. Backed Views

The results returned by:

``` java
entrySet()
keySet()
values()
```

are views backed by the map rather than unrelated copies.

Conceptually:

``` text
TreeMap
   |
   +── entrySet() ──┐
   |
   +── keySet()  ───┼── Views of the same map
   |
   +── values()  ───┘
```

Changes to the underlying map can therefore be reflected in these views.

This is an important concept as you move into more advanced Java
Collections usage.

# 32. Common Beginner Mistakes

## Mistake 1 --- Expecting insertion order

Given:

``` java
map.put("Laptop", ...);
map.put("Smartphone", ...);
map.put("Tablet", ...);
map.put("Monitor", ...);
```

do not assume iteration will be:

``` text
Laptop
Smartphone
Tablet
Monitor
```

A natural-order TreeMap sorts the keys:

``` text
Laptop
Monitor
Smartphone
Tablet
```

------------------------------------------------------------------------

## Mistake 2 --- Using `keySet()` when both key and value are required

This works:

``` java
for (String key : map.keySet()) {
    Double value = map.get(key);
}
```

But when you need both for every mapping, prefer:

``` java
for (Map.Entry<String, Double> entry :
        map.entrySet()) {
    ...
}
```

or:

``` java
map.forEach((key, value) -> ...);
```

------------------------------------------------------------------------

## Mistake 3 --- Forgetting `hasNext()`

Incorrect iterator logic can attempt to call `next()` when no entry
remains.

Correct pattern:

``` java
while (iterator.hasNext()) {
    Map.Entry<String, Double> entry =
            iterator.next();
}
```

------------------------------------------------------------------------

## Mistake 4 --- Confusing `entrySet()` with `keySet()`

Remember:

``` text
entrySet()
    → key + value

keySet()
    → key only
```

------------------------------------------------------------------------

## Mistake 5 --- Assuming values are sorted by value

When iterating:

``` java
productPrices.values()
```

the values are encountered according to their corresponding **sorted key
order**.

The `TreeMap` is not sorting the values themselves.

# 33. Quick Cheat Sheet

## Key + Value --- Java 8

``` java
map.forEach(
        (key, value) ->
                System.out.println(
                        key + "=" + value
                )
);
```

## Key + Value --- Iterator

``` java
Iterator<Map.Entry<K, V>> iterator =
        map.entrySet().iterator();

while (iterator.hasNext()) {

    Map.Entry<K, V> entry =
            iterator.next();

    System.out.println(
            entry.getKey()
    );

    System.out.println(
            entry.getValue()
    );
}
```

## Keys Only

``` java
for (K key : map.keySet()) {
    System.out.println(key);
}
```

## Values Only

``` java
for (V value : map.values()) {
    System.out.println(value);
}
```

## Key + Value --- Enhanced `for`

``` java
for (Map.Entry<K, V> entry :
        map.entrySet()) {

    System.out.println(
            entry.getKey() +
            "=" +
            entry.getValue()
    );
}
```

# 34. Interview / Exam Points

1.  `Map.forEach()` was added as a default method in Java 8.
2.  `Map.forEach()` provides the key and value to a `BiConsumer`.
3.  A lambda can be used to implement the `BiConsumer`.
4.  `entrySet()` provides access to `Map.Entry<K,V>` objects.
5.  `Map.Entry.getKey()` returns the key.
6.  `Map.Entry.getValue()` returns the value.
7.  `iterator()` creates an iterator over the collection/view.
8.  `hasNext()` checks whether another element remains.
9.  `next()` returns the next element and advances the iterator.
10. `keySet()` is appropriate when only keys are required.
11. `values()` is appropriate when only values are required.
12. `values()` returns a `Collection` because map values can contain
    duplicates.
13. `keySet()` returns a `Set` because map keys are unique.
14. TreeMap iteration follows its key ordering.
15. With natural ordering, String keys iterate according to natural
    String order.
16. A custom comparator changes TreeMap iteration order.
17. `entrySet()`, `keySet()`, and `values()` are backed views of the
    map.
18. If both key and value are required, `Map.forEach()` or `entrySet()`
    is usually clearer than `keySet()` plus repeated `get()`.

# Final Summary

The four main approaches from this lecture are:

``` java
// 1. Key + value directly
map.forEach((key, value) -> ...);
```

``` java
// 2. Key + value through Map.Entry
Iterator<Map.Entry<K, V>> iterator =
        map.entrySet().iterator();
```

``` java
// 3. Keys only
for (K key : map.keySet()) {
    ...
}
```

``` java
// 4. Values only
for (V value : map.values()) {
    ...
}
```

The easiest memory rule is:

``` text
forEach()
    → KEY + VALUE directly

entrySet()
    → ENTRY → KEY + VALUE

keySet()
    → KEY only

values()
    → VALUE only
```

And the most important `TreeMap` rule:

``` text
The iteration follows the map's
SORTED KEY ORDER,
not insertion order.
```
