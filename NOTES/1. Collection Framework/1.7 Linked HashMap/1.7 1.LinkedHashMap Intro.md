# Java `LinkedHashMap` --- Beginner-Friendly Notes

## 1. What is a `LinkedHashMap`?

`LinkedHashMap` is an implementation of Java's `Map` interface.

It combines two data structures:

-   **Hash table** --- provides fast key-based lookup.
-   **Doubly linked list** --- maintains a predictable iteration order.

In the normal/default configuration, that order is the **insertion
order**: the order in which entries were added.

`LinkedHashMap` belongs to the `java.util` package.

``` java
import java.util.LinkedHashMap;
import java.util.Map;
```

------------------------------------------------------------------------

## 2. Class Hierarchy

A simplified hierarchy is:

``` text
Map (interface)
   ↑
HashMap
   ↑
LinkedHashMap
```

More precisely:

-   `HashMap` implements the `Map` interface.
-   `LinkedHashMap` extends `HashMap`.

Because `LinkedHashMap` extends `HashMap`, it provides familiar map
operations such as `put()`, `get()`, `remove()`, `containsKey()`, and
`entrySet()`, while also maintaining linked ordering information.

------------------------------------------------------------------------

## 3. `HashMap` vs `LinkedHashMap`

The most important beginner-level difference is iteration order.

  Feature                                 `HashMap`   `LinkedHashMap`
  --------------------------------------- ----------- -----------------
  Key-value storage                       Yes         Yes
  Duplicate keys                          No          No
  One `null` key                          Yes         Yes
  `null` values                           Yes         Yes
  Predictable insertion-order iteration   No          Yes, by default
  Thread-safe                             No          No

### Example

``` java
Map<String, Integer> stock = new LinkedHashMap<>();

stock.put("Apple", 50);
stock.put("Banana", 30);
stock.put("Orange", 20);
stock.put("Grapes", 40);

System.out.println(stock);
```

Typical output:

``` text
{Apple=50, Banana=30, Orange=20, Grapes=40}
```

The entries appear in the same order in which they were inserted.

------------------------------------------------------------------------

## 4. Duplicate Keys Are Not Allowed

A `LinkedHashMap` cannot contain duplicate keys.

Each key must be unique.

``` java
Map<String, Integer> stock = new LinkedHashMap<>();

stock.put("Apple", 50);
stock.put("Apple", 75);

System.out.println(stock);
```

Output:

``` text
{Apple=75}
```

The second `put()` does **not** create another `"Apple"` entry.

Instead:

``` text
Apple → 50
     ↓
put("Apple", 75)
     ↓
Apple → 75
```

The value associated with the existing key is replaced.

> **Remember:** Map keys are unique, but different keys may have the
> same value.

------------------------------------------------------------------------

## 5. `null` Key and `null` Values

Like `HashMap`, `LinkedHashMap` allows:

-   One `null` key
-   Multiple `null` values

Example:

``` java
Map<String, String> users = new LinkedHashMap<>();

users.put(null, "Unknown User");
users.put("A101", null);
users.put("A102", null);

System.out.println(users);
```

This is valid Java.

There can only be one `null` key because keys must be unique.

------------------------------------------------------------------------

## 6. Insertion Order

By default, `LinkedHashMap` remembers the order in which entries are
inserted.

``` java
Map<Integer, String> employees = new LinkedHashMap<>();

employees.put(101, "John");
employees.put(102, "Sarah");
employees.put(103, "David");
```

The insertion sequence is:

``` text
101 → John
102 → Sarah
103 → David
```

When iterating:

``` java
for (Map.Entry<Integer, String> entry : employees.entrySet()) {
    System.out.println(entry.getKey() + " -> " + entry.getValue());
}
```

Output:

``` text
101 -> John
102 -> Sarah
103 -> David
```

This predictable iteration order is one of the main reasons to choose
`LinkedHashMap` over `HashMap`.

------------------------------------------------------------------------

## 7. Updating a Value

Updating the value of an existing key does not normally move that entry
to the end when using the default insertion-order mode.

``` java
Map<String, Integer> stock = new LinkedHashMap<>();

stock.put("Apple", 50);
stock.put("Banana", 30);
stock.put("Orange", 20);

stock.put("Banana", 35);

System.out.println(stock);
```

Output:

``` text
{Apple=50, Banana=35, Orange=20}
```

`Banana` keeps its original position, but its value changes from `30` to
`35`.

## 8. Common Operations

### Add or Update

``` java
stock.put("Apple", 50);
```

### Retrieve

``` java
Integer quantity = stock.get("Apple");
```

### Check for a Key

``` java
boolean exists = stock.containsKey("Apple");
```

### Remove

``` java
stock.remove("Apple");
```

### Get Number of Entries

``` java
int size = stock.size();
```

### Check Whether Empty

``` java
boolean empty = stock.isEmpty();
```

### Iterate Through Entries

``` java
for (Map.Entry<String, Integer> entry : stock.entrySet()) {
    System.out.println(entry.getKey() + " = " + entry.getValue());

```

## 9. Complete Example

``` java
import java.util.LinkedHashMap;
import java.util.Map;

public class LinkedHashMapExample {

    public static void main(String[] args) {

        Map<String, Integer> stock = new LinkedHashMap<>();

        // Add entries
        stock.put("Apple", 50);
        stock.put("Banana", 30);
        stock.put("Orange", 20);
        stock.put("Grapes", 40);

        // Update an existing key
        stock.put("Banana", 35);

        // Retrieve
        Integer appleQuantity = stock.get("Apple");

        System.out.println("Apple Quantity: " + appleQuantity);

        // Iterate in insertion order
        for (Map.Entry<String, Integer> entry : stock.entrySet()) {
            System.out.println(entry.getKey() + " -> " + entry.getValue());
        }
    }
}
```

Expected order:

``` text
Apple Quantity: 50
Apple -> 50
Banana -> 35
Orange -> 20
Grapes -> 40
```

------------------------------------------------------------------------

## 10. Thread Safety

`LinkedHashMap` is **not thread-safe**.

If multiple threads modify the same `LinkedHashMap` concurrently,
external synchronization may be required.

For example, Java provides synchronized wrappers:

``` java
Map<String, Integer> map =
        java.util.Collections.synchronizedMap(new LinkedHashMap<String, Integer>());
```

For concurrent applications, `ConcurrentHashMap` is another important
map implementation to learn, although it has different behavior and does
**not** simply act as an insertion-ordered replacement for
`LinkedHashMap`.

------------------------------------------------------------------------

## 11. How to Choose

Use a `HashMap` when:

-   You need normal key-value storage.
-   You do not care about iteration order.
-   You want a straightforward general-purpose map.

Use a `LinkedHashMap` when:

-   You need key-value storage.
-   You also want predictable iteration order.
-   You want entries to normally appear in the order they were inserted.

A simple rule:

``` text
Need Map?
   |
   +-- Don't care about iteration order --> HashMap
   |
   +-- Need predictable insertion order --> LinkedHashMap
```

------------------------------------------------------------------------

## 12. Important Interview / Exam Points

1.  `LinkedHashMap` is part of `java.util`.
2.  It extends `HashMap`.
3.  It implements map behavior using hashing plus linked ordering.
4.  Keys must be unique.
5.  Adding an existing key replaces its value.
6.  It permits one `null` key and multiple `null` values.
7.  It maintains insertion-order iteration by default.
8.  It is not thread-safe.
9.  `HashMap` does not guarantee insertion-order iteration.
10. `LinkedHashMap` is useful when both map lookup and predictable
    iteration order are required.

------------------------------------------------------------------------

## 13. One-Line Summary

> **`LinkedHashMap` provides `HashMap`-style key-value storage while
> maintaining predictable iteration order, normally the order in which
> entries were inserted.**
