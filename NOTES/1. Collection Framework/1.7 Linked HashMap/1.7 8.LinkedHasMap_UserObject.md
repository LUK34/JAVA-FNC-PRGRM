# Java `LinkedHashMap` with User-Defined Objects

## Overview

This lesson explains how to create a Java `LinkedHashMap` whose values
are **user-defined objects**.

You will learn how to:

-   Create a custom `Todo` class.
-   Define instance variables, a constructor, getters, `equals()`,
    `hashCode()`, and `toString()`.
-   Use an `Integer` as the map key and a `Todo` object as the value.
-   Add custom objects to a `LinkedHashMap` using `put()`.
-   Iterate through the map and access fields from the custom objects.
-   Understand why `equals()`, `hashCode()`, and `toString()` are
    useful.

All examples are compatible with **Java 8**.

------------------------------------------------------------------------

# 1. What Is a User-Defined Object?

Java already provides built-in classes such as:

``` java
String
Integer
Double
ArrayList
LinkedHashMap
```

But developers can also create their own classes.

For example:

``` java
class Todo {
    // fields and methods
}
```

`Todo` is a **user-defined class**.

An object created from it:

``` java
new Todo(...)
```

is a **user-defined object**.

------------------------------------------------------------------------

# 2. Our Goal

We want to create a map like this:

``` text
KEY                 VALUE

Todo ID             Todo Object
   │                     │
   v                     v
   1  →  Todo{id=1, name="Learn Java", ...}

   2  →  Todo{id=2, name="Learn Spring Boot", ...}
```

The map type will therefore be:

``` java
Map<Integer, Todo>
```

Here:

``` text
Integer → Key type
Todo    → Value type
```

------------------------------------------------------------------------

# 3. Create the `Todo` Class

Start with:

``` java
class Todo {

    private int todoId;
    private String todoName;
    private String todoDescription;
```

The class contains three instance variables:

  Field               Type       Purpose
  ------------------- ---------- -------------------------
  `todoId`            `int`      Unique identifier
  `todoName`          `String`   Name/title of the task
  `todoDescription`   `String`   Description of the task


# 6. Override `equals()` and `hashCode()`

The lecture defines two `Todo` objects as equal based on:

``` text
todoId
```

For example:

``` text
Todo A
todoId = 1

Todo B
todoId = 1

        ↓

Considered equal
```

An implementation is:

``` java
@Override
public boolean equals(Object o) {

    if (this == o) {
        return true;
    }

    if (o == null || getClass() != o.getClass()) {
        return false;
    }

    Todo todo = (Todo) o;

    return todoId == todo.todoId;
}

@Override
public int hashCode() {
    return Integer.hashCode(todoId);
}
```

For Java 8, `Integer.hashCode(todoId)` is valid.

------------------------------------------------------------------------

# 7. Why Override Both `equals()` and `hashCode()`?

If you override `equals()`, you should also provide a consistent
`hashCode()` implementation.

Our equality rule is:

``` text
Same todoId
    ↓
Objects are equal
```

Therefore the hash code should also be derived from:

``` text
todoId
```

This is particularly important when custom objects are used in
hash-based collections such as:

``` java
HashMap
LinkedHashMap
HashSet
LinkedHashSet
```

### Important detail for this example

Our `Todo` object is being used as the **value**:

``` java
Map<Integer, Todo>
```

The map hashes the `Integer` key, not the `Todo` value.

So overriding `Todo.equals()` and `Todo.hashCode()` is not required
merely to store `Todo` as a value. However, it is still good
object-modeling practice when `Todo` has a meaningful identity, and it
becomes especially important if `Todo` is later used as a map key or in
a `HashSet`.

------------------------------------------------------------------------

# 8. Override `toString()`

`toString()` controls how an object is represented when printed.

Example:

``` java
@Override
public String toString() {

    return "Todo{" +
            "todoId=" + todoId +
            ", todoName='" + todoName + '\'' +
            ", todoDescription='" + todoDescription + '\'' +
            '}';
}
```

Without a useful `toString()`, printing an object may produce something
similar to:

``` text
Todo@5acf9800
```

With our overridden `toString()`:

``` text
Todo{todoId=1, todoName='Learn Java Programming',
todoDescription='Learn Java programming with examples'}
```

This is much easier to read and debug.

# 9. Complete `Todo` Class

``` java
class Todo {

    private int todoId;
    private String todoName;
    private String todoDescription;

    public Todo(
            int todoId,
            String todoName,
            String todoDescription) {

        this.todoId = todoId;
        this.todoName = todoName;
        this.todoDescription = todoDescription;
    }

    public int getTodoId() {
        return todoId;
    }

    public String getTodoName() {
        return todoName;
    }

    public String getTodoDescription() {
        return todoDescription;
    }

    @Override
    public boolean equals(Object o) {

        if (this == o) {
            return true;
        }

        if (o == null || getClass() != o.getClass()) {
            return false;
        }

        Todo todo = (Todo) o;

        return todoId == todo.todoId;
    }

    @Override
    public int hashCode() {
        return Integer.hashCode(todoId);
    }

    @Override
    public String toString() {

        return "Todo{" +
                "todoId=" + todoId +
                ", todoName='" + todoName + '\'' +
                ", todoDescription='" +
                todoDescription + '\'' +
                '}';
    }
}
```

# 11. Add User-Defined Objects Using `put()`

Add the first task:

``` java
todoMap.put(
        1,
        new Todo(
                1,
                "Learn Java Programming",
                "Learn Java programming with examples"
        )
);
```

Add another:

``` java
todoMap.put(
        2,
        new Todo(
                2,
                "Learn Spring Boot",
                "Learn Spring Boot with examples"
        )
);
```

The structure becomes:

``` text
todoMap

1
│
└── Todo
    ├── todoId = 1
    ├── todoName = Learn Java Programming
    └── todoDescription = Learn Java programming with examples


2
│
└── Todo
    ├── todoId = 2
    ├── todoName = Learn Spring Boot
    └── todoDescription = Learn Spring Boot with examples
```

------------------------------------------------------------------------

# 12. Why Is the ID Present Twice?

You may notice:

``` java
todoMap.put(
        1,
        new Todo(1, ...)
);
```

There is an ID in both:

``` text
Map Key  → 1
Todo ID  → 1
```

The map key provides direct lookup:

``` java
todoMap.get(1);
```

while `todoId` is part of the `Todo` object's own data.

This design is common, but your application should keep both IDs
consistent if they represent the same identity.

# 14. Retrieve a `Todo` by ID

Because the key is the Todo ID:

``` java
Todo todo = todoMap.get(1);
```

``` java
System.out.println(todo.getTodoName());
```

Output:

``` text
Learn Java Programming
```

The lookup flow is:

``` text
todoMap.get(1)
      |
      v
Find key 1
      |
      v
Return Todo object
      |
      v
todo.getTodoName()
```

# 15. Iterate Through the User-Defined Objects

Using Java 8:

``` java
todoMap.forEach(
        (id, todo) -> {

            System.out.println(
                    "ID: " + id
            );

            System.out.println(
                    "Name: " +
                    todo.getTodoName()
            );

            System.out.println(
                    "Description: " +
                    todo.getTodoDescription()
            );
        }
);
```

This demonstrates an important concept:

``` text
id
↓
Map key


todo
↓
Todo object
```

You can then access the object's fields through its getter methods.

------------------------------------------------------------------------

# 16. Iterate Using `entrySet()`

You can also write:

``` java
for (Map.Entry<Integer, Todo> entry :
        todoMap.entrySet()) {

    Integer id = entry.getKey();
    Todo todo = entry.getValue();

    System.out.println(
            id + " -> " + todo.getTodoName()
    );
}
```

Here:

``` text
entry.getKey()
      ↓
Integer ID


entry.getValue()
      ↓
Todo object
```

# 17. Complete Runnable Example

``` java
import java.util.LinkedHashMap;
import java.util.Map;

class Todo {

    private int todoId;
    private String todoName;
    private String todoDescription;

    public Todo(
            int todoId,
            String todoName,
            String todoDescription) {

        this.todoId = todoId;
        this.todoName = todoName;
        this.todoDescription = todoDescription;
    }

    public int getTodoId() {
        return todoId;
    }

    public String getTodoName() {
        return todoName;
    }

    public String getTodoDescription() {
        return todoDescription;
    }

    @Override
    public boolean equals(Object o) {

        if (this == o) {
            return true;
        }

        if (o == null || getClass() != o.getClass()) {
            return false;
        }

        Todo todo = (Todo) o;

        return todoId == todo.todoId;
    }

    @Override
    public int hashCode() {
        return Integer.hashCode(todoId);
    }

    @Override
    public String toString() {

        return "Todo{" +
                "todoId=" + todoId +
                ", todoName='" + todoName + '\'' +
                ", todoDescription='" +
                todoDescription + '\'' +
                '}';
    }
}

public class LinkedHashMapUserDefinedObjectsExample {

    public static void main(String[] args) {

        Map<Integer, Todo> todoMap =
                new LinkedHashMap<>();

        todoMap.put(
                1,
                new Todo(
                        1,
                        "Learn Java Programming",
                        "Learn Java programming with examples"
                )
        );

        todoMap.put(
                2,
                new Todo(
                        2,
                        "Learn Spring Boot",
                        "Learn Spring Boot with examples"
                )
        );

        System.out.println(todoMap);

        System.out.println(
                "\nIterating Todo Map:"
        );

        todoMap.forEach(
                (id, todo) -> {

                    System.out.println(
                            "Todo ID: " + id
                    );

                    System.out.println(
                            "Todo Name: " +
                            todo.getTodoName()
                    );

                    System.out.println(
                            "Description: " +
                            todo.getTodoDescription()
                    );

                    System.out.println();
                }
        );
    }
}
```

# 18. LinkedHashMap Insertion Order

Suppose you insert:

``` java
todoMap.put(1, todo1);
todoMap.put(2, todo2);
todoMap.put(3, todo3);
```

The default iteration order is:

``` text
1 → todo1
2 → todo2
3 → todo3
```

This is one of the main reasons to choose `LinkedHashMap` when
predictable iteration order matters.

------------------------------------------------------------------------

# 19. What Happens with a Duplicate Map Key?

Suppose:

``` java
todoMap.put(
        1,
        new Todo(
                1,
                "Learn Java",
                "Original task"
        )
);
```

Then:

``` java
todoMap.put(
        1,
        new Todo(
                1,
                "Master Java",
                "Updated task"
        )
);
```

Because map keys are unique, key `1` is not added twice.

Instead:

``` text
Key 1
   |
   v
Old Todo object
   |
   v
REPLACED
   |
   v
New Todo object
```

So `put()` can both add and replace values.

# 21. Common Beginner Mistakes

## Mistake 1 --- Using the wrong generic type

Incorrect:

``` java
Map<Integer, String> todoMap =
        new LinkedHashMap<>();
```

if you intend to store `Todo` objects.

Correct:

``` java
Map<Integer, Todo> todoMap =
        new LinkedHashMap<>();
```

------------------------------------------------------------------------

## Mistake 2 --- Forgetting `new Todo(...)`

This:

``` java
todoMap.put(1, Todo);
```

is not how you create an object.

Use:

``` java
todoMap.put(
        1,
        new Todo(1, "Learn Java", "Description")
);
```

unless you already have a `Todo` variable.

------------------------------------------------------------------------

## Mistake 3 --- Confusing the key with the value

For:

``` java
Map<Integer, Todo>
```

remember:

``` text
Integer
   ↓
KEY


Todo
 ↓
VALUE
```

------------------------------------------------------------------------

## Mistake 4 --- Thinking `toString()` changes the object

`toString()` only provides a textual representation of the object.

It does not change its fields.

------------------------------------------------------------------------

## Mistake 5 --- Thinking `equals()` alone is enough

If your class overrides `equals()`, provide a consistent `hashCode()`
implementation as well.

# 23. Interview / Exam Points

1.  A `LinkedHashMap` can store user-defined objects as keys or values.
2.  `Map<Integer, Todo>` means the key is `Integer` and the value is
    `Todo`.
3.  `put()` adds the custom object to the map as a value in this
    example.
4.  `get(key)` retrieves the corresponding `Todo`.
5.  `LinkedHashMap` provides predictable ordering; by default it uses
    insertion order.
6.  Map keys must be unique.
7.  Reusing an existing key replaces its associated value.
8.  `toString()` makes object output easier to read.
9.  `equals()` defines logical equality between objects.
10. `hashCode()` must be consistent with `equals()`.
11. In this example, equality is based on `todoId`.
12. Since `Todo` is the value rather than the key, the map itself hashes
    the `Integer` keys.

# Final Summary

A `LinkedHashMap` is not limited to simple values such as `String` and
`Integer`.

You can store complete user-defined objects:

``` java
Map<Integer, Todo> todoMap =
        new LinkedHashMap<>();
```

Then:

``` text
Integer ID
    ↓
   KEY
    |
    v
Todo Object
    ↓
  VALUE
```

The basic workflow is:

``` text
Create Todo class
       ↓
Add fields
       ↓
Add constructor/getters
       ↓
Define equals() + hashCode()
       ↓
Define toString()
       ↓
Create LinkedHashMap<Integer, Todo>
       ↓
Add Todo objects with put()
       ↓
Retrieve with get()
       ↓
Iterate and process objects
```

This same pattern is widely applicable to real Java applications where
IDs are mapped to domain objects or DTOs.
