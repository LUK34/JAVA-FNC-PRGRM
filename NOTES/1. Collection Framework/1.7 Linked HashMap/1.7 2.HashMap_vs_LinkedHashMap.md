# Java `HashMap` vs `LinkedHashMap`

## Overview

Both `HashMap` and `LinkedHashMap` are implementations of Java's `Map`
interface. They store data as **key-value pairs**, but the main
difference is how they handle the **iteration order** of those entries.

A simple way to remember the difference is:

``` text
HashMap       → Fast key-value storage; no guaranteed iteration order
LinkedHashMap → Fast key-value storage + predictable iteration order
```

------------------------------------------------------------------------

## 1. Internal Structure

### `HashMap`

`HashMap` uses a **hash-based data structure** to store key-value pairs.

``` java
Map<String, Integer> map = new HashMap<>();
```

Hashing allows Java to efficiently locate values using their keys.

Conceptually:

``` text
Key
 ↓
Hash calculation
 ↓
Bucket/location
 ↓
Value
```

The important point is that `HashMap` does **not guarantee
insertion-order iteration**.

------------------------------------------------------------------------

### `LinkedHashMap`

`LinkedHashMap` extends `HashMap` and additionally maintains links
between entries.

``` java
Map<String, Integer> map = new LinkedHashMap<>();
```

It combines:

``` text
Hash-based storage
       +
Linked ordering between entries
```

By default, this allows `LinkedHashMap` to iterate through entries in
**insertion order**.

Simplified class relationship:

``` text
Map
 ↑
HashMap
 ↑
LinkedHashMap
```

------------------------------------------------------------------------

## 2. Order of Elements

This is the most important difference.

### `HashMap`

`HashMap` does not guarantee that entries will be iterated in the same
order in which they were inserted.

Example:

``` java
Map<String, Integer> stock = new HashMap<>();

stock.put("Apple", 50);
stock.put("Banana", 30);
stock.put("Orange", 20);
stock.put("Grapes", 40);

for (Map.Entry<String, Integer> entry : stock.entrySet()) {
    System.out.println(entry.getKey());
}
```

You should **not rely on** the output being:

``` text
Apple
Banana
Orange
Grapes
```

Even if a particular run happens to display that order, `HashMap` does
not promise it.

------------------------------------------------------------------------

### `LinkedHashMap`

`LinkedHashMap`, in its normal insertion-order mode, preserves the order
in which entries were inserted.

``` java
Map<String, Integer> stock = new LinkedHashMap<>();

stock.put("Apple", 50);
stock.put("Banana", 30);
stock.put("Orange", 20);
stock.put("Grapes", 40);

for (Map.Entry<String, Integer> entry : stock.entrySet()) {
    System.out.println(entry.getKey());
}
```

Output:

``` text
Apple
Banana
Orange
Grapes
```

So:

``` text
Insertion:
Apple → Banana → Orange → Grapes

LinkedHashMap iteration:
Apple → Banana → Orange → Grapes
```

------------------------------------------------------------------------

## 3. Performance

Both `HashMap` and `LinkedHashMap` provide efficient common map
operations.

Typical operations include:

``` java
put()
get()
remove()
containsKey()
```

For normal usage, these operations are generally expected to be very
fast, commonly described as **O(1) average time** for hash-based lookup
operations.

### `HashMap`

`HashMap` generally has less overhead because it does not need to
maintain linked ordering information.

### `LinkedHashMap`

`LinkedHashMap` has some additional memory and processing overhead
because it maintains links used for predictable iteration order.

Therefore, if ordering is unnecessary, `HashMap` is usually the simpler
choice.

> Do not assume the practical performance difference will always be
> significant. Choose primarily based on whether predictable iteration
> order is required, then benchmark if performance is critical.

------------------------------------------------------------------------

## 4. `null` Keys and Values

Both `HashMap` and `LinkedHashMap` allow:

-   **One `null` key**
-   **Multiple `null` values**

### `HashMap`

``` java
Map<String, String> map = new HashMap<>();

map.put(null, "Unknown");
map.put("A", null);
map.put("B", null);
```

This is valid.

### `LinkedHashMap`

``` java
Map<String, String> map = new LinkedHashMap<>();

map.put(null, "Unknown");
map.put("A", null);
map.put("B", null);
```

This is also valid.

Why only one `null` key?

Because map keys must be unique.

------------------------------------------------------------------------

## 5. Duplicate Keys

Neither `HashMap` nor `LinkedHashMap` allows duplicate keys.

For example:

``` java
Map<String, Integer> stock = new HashMap<>();

stock.put("Apple", 50);
stock.put("Apple", 75);
```

The second operation replaces the value associated with `"Apple"`.

Result:

``` text
Apple → 75
```

The same behavior applies to `LinkedHashMap`.

## 6. Comparison Table

  Feature                                 `HashMap`     `LinkedHashMap`
  --------------------------------------- ------------- -----------------
  Implements `Map` behavior               Yes           Yes
  Hash-based storage                      Yes           Yes
  Extends `HashMap`                       No            Yes
  Predictable insertion-order iteration   No            Yes, by default
  Duplicate keys                          Not allowed   Not allowed
  One `null` key                          Allowed       Allowed
  Multiple `null` values                  Allowed       Allowed
  Average hash lookup                     O(1)          O(1)
  Ordering overhead                       Lower         Higher
  Thread-safe                             No            No

## 7. When Should You Use `HashMap`?

Use `HashMap` when:

-   You need key-value storage.
-   You need fast lookup using keys.
-   The iteration order does not matter.
-   You do not need entries returned in insertion order.

Example:

``` java
Map<Long, String> patientNames = new HashMap<>();

patientNames.put(1001L, "John");
patientNames.put(1002L, "David");
patientNames.put(1003L, "Sarah");
```

If you only need:

``` java
patientNames.get(1002L);
```

and do not care about iteration order, `HashMap` is a natural choice.

------------------------------------------------------------------------

## 8. When Should You Use `LinkedHashMap`?

Use `LinkedHashMap` when:

-   You need key-value storage.
-   You need fast lookup.
-   You also need predictable iteration order.
-   You want entries to normally appear in the order they were inserted.

Example:

``` java
Map<String, String> workflow = new LinkedHashMap<>();

workflow.put("STEP_1", "Register Patient");
workflow.put("STEP_2", "Doctor Consultation");
workflow.put("STEP_3", "Laboratory");
workflow.put("STEP_4", "Complete");
```

When iterated, the steps remain in insertion order:

``` text
STEP_1
STEP_2
STEP_3
STEP_4
```

------------------------------------------------------------------------

## 9. Complete Example

``` java
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.Map;

public class MapComparison {

    public static void main(String[] args) {

        Map<String, Integer> hashMap = new HashMap<>();

        hashMap.put("Apple", 50);
        hashMap.put("Banana", 30);
        hashMap.put("Orange", 20);
        hashMap.put("Grapes", 40);

        System.out.println("HashMap:");

        for (Map.Entry<String, Integer> entry : hashMap.entrySet()) {
            System.out.println(
                entry.getKey() + " -> " + entry.getValue()
            );
        }

        System.out.println();

        Map<String, Integer> linkedHashMap =
                new LinkedHashMap<>();

        linkedHashMap.put("Apple", 50);
        linkedHashMap.put("Banana", 30);
        linkedHashMap.put("Orange", 20);
        linkedHashMap.put("Grapes", 40);

        System.out.println("LinkedHashMap:");

        for (Map.Entry<String, Integer> entry : linkedHashMap.entrySet()) {
            System.out.println(
                entry.getKey() + " -> " + entry.getValue()
            );
        }
    }
}
```

For `LinkedHashMap`, the expected iteration order is:

``` text
Apple -> 50
Banana -> 30
Orange -> 20
Grapes -> 40
```

For `HashMap`, do not write code that depends on this insertion order.

## 10. Important Interview Points

1.  Both `HashMap` and `LinkedHashMap` implement `Map` behavior.
2.  `LinkedHashMap` extends `HashMap`.
3.  `HashMap` does not guarantee insertion-order iteration.
4.  `LinkedHashMap` maintains insertion-order iteration by default.
5.  Both require unique keys.
6.  An existing key's value is replaced when the same key is inserted
    again.
7.  Both allow one `null` key.
8.  Both allow multiple `null` values.
9.  Both provide efficient average-time hash-based lookup.
10. `LinkedHashMap` has additional overhead for maintaining ordering.
11. Neither `HashMap` nor `LinkedHashMap` is inherently thread-safe.

## Final Summary

The primary practical difference is **iteration order**.

**`HashMap`**

``` text
Fast key-value lookup
+
No guaranteed insertion-order iteration
```

**`LinkedHashMap`**

``` text
Fast key-value lookup
+
Predictable insertion-order iteration
+
Small additional ordering overhead
```

### One-line rule

> **Use `HashMap` when order does not matter. Use `LinkedHashMap` when
> predictable insertion-order iteration matters.**
